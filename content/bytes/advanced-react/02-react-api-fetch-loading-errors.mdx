## Why this concept matters

Server responses can take time, fail or contain unexpected data. **You will learn:** explain the idea, follow the execution flow, read a compact example and try one realistic decision. Basic React components, props and useState are helpful; this Byte also works as a standalone introduction.

## Start with a familiar scenario

Ordering online shows the idea: an order can be pending, confirmed, or failed. API-backed screens need the same explicit states.

**Vocabulary:** request, response, loading, error, retry, server state.

## Understand the core concept

Keep remote data distinct from local UI state. Fetch may resolve on HTTP errors, so check response.ok. Represent loading, success and error; provide a retry action. Protect against stale requests. For larger systems, server-state libraries can handle caching and synchronization.

**When not to use it:** Select the simplest React feature that solves the actual problem. An advanced API or Hook is not a requirement for every component.

**Step 2 — Read the implementation.** The example is intentionally small; it isolates the concept before introducing additional application architecture.

```tsx
type Issue = { id: number; title: string };
async function loadIssues(signal: AbortSignal): Promise<Issue[]> {
  const response = await fetch('/api/issues', { signal });
  if (!response.ok) throw new Error('Could not load issues');
  return (await response.json()) as Issue[];
}
```

## Common mistakes and recovery

Assuming fetch rejects on HTTP 404; showing a blank screen during loading; displaying stale results.

When behavior is surprising, verify the inputs and first observable failure. Check browser-console warnings, network responses and visible error states before adding complexity.

## Interview Bit and key takeaways

**Interview question:** When should React useEffect fetch data?

**Simple answer:** An Effect can synchronize with an external API in a client-only app, but framework loaders or dedicated server-state tools may be preferable. Handle pending, errors and cancellation.

**Eight takeaways:**

1. Start by describing the user's problem.
2. Identify which values are local and which originate outside React.
3. Use explicit types and state transitions where helpful.
4. Prefer readable components over one large file.
5. Show loading, invalid and error states clearly.
6. Verify the observable result after changes.
7. Avoid unnecessary Effects and premature optimization.
8. Choose tools according to actual complexity.
