## Why this concept matters

Different screens need URLs, and some values must be shared between distant components. **You will learn:** explain the idea, follow the execution flow, read a compact example and try one realistic decision. Basic React components, props and useState are helpful; this Byte also works as a standalone introduction.

## Start with a familiar scenario

A building has numbered rooms. A URL points to a room; shared context is like a building-wide theme setting, while each room still owns its local controls.

**Vocabulary:** route, navigation, context, provider, custom Hook.

## Understand the core concept

React Router maps URL paths to components. Declarative mode uses BrowserRouter, Routes, Route and Link. Context makes shared values available without repetitive prop passing. Custom Hooks reuse Hook-driven logic and start with use.

**When not to use it:** Select the simplest React feature that solves the actual problem. An advanced API or Hook is not a requirement for every component.

## Guided code walkthrough

**Step 1 — Identify the inputs and the expected output.** Different screens need URLs, and some values must be shared between distant components.

**Step 2 — Read the implementation.** The example is intentionally small; it isolates the concept before introducing additional application architecture.

```tsx
import { BrowserRouter, Link, Route, Routes } from 'react-router';
export default function App() {
  return <BrowserRouter>
    <nav><Link to='/issues'>Issues</Link></nav>
    <Routes>
      <Route path='/issues' element={<h1>Issue list</h1>} />
      <Route path='/issues/:id' element={<h1>Issue details</h1>} />
    </Routes>
  </BrowserRouter>;
}
```

**Step 3 — Predict the browser result.** Clicking Issues navigates to /issues and displays the Issue list. The nested route requires host fallback configuration on refresh.

**Step 4 — Explain the execution.** URL; then Router match; then component; then shared context; then visible page.

**Step 5 — Verify.** Run the example in a React/TypeScript project with the appropriate installed package or mock API. The purpose is understanding behavior, not copy-pasting an unexplained application.

## Common mistakes and recovery

Putting every input in Context; using ordinary anchors for all internal navigation; assuming routing stores data.

When behavior is surprising, verify the inputs and first observable failure. Check browser-console warnings, network responses and visible error states before adding complexity.

## Interview Bit and key takeaways

**Interview question:** When should Context replace props?

**Simple answer:** Use Context when many distant components require the same value. Props remain clearer for nearby components.

**Eight takeaways:**

1. Start by describing the user's problem.
2. Identify which values are local and which originate outside React.
3. Use explicit types and state transitions where helpful.
4. Prefer readable components over one large file.
5. Show loading, invalid and error states clearly.
6. Verify the observable result after changes.
7. Avoid unnecessary Effects and premature optimization.
8. Choose tools according to actual complexity.
