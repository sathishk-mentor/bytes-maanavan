## Quick Start
Conversation history is what happened. Agent memory is the selected information allowed to influence a future step. Separate temporary context, durable preferences and protected records.

<MongoDBConceptLab variant="memory" />

## Start from Basics
Use `user_id` for ownership, `session_id` for one conversation and timestamps for ordering. Confirm every requested session belongs to the authenticated user.

## Core Explanation
```javascript
{ user_id: "cust_5521", session_id: "sess_2291", role: "user",
  content: "Explain in Tamil next time",
  created_at: ISODate("2026-09-18T10:15:00Z"),
  expires_at: ISODate("2026-10-18T10:15:00Z") }
```
Retrieve only the recent window needed. Store durable preferences separately so users can inspect, correct or delete them.

## Types and Components
- Working context: recent turns for this request.
- Conversation summary: compressed history with source pointers.
- Durable preference: explicit, user-editable choice.
- Audit record: protected evidence retained by policy.

## History vs Memory
| Item | History | Memory |
|---|---|---|
| Meaning | Recorded events | Selected future context |
| Loading | On demand | Only when relevant |
| Control | Export/delete | Inspect/correct/delete |

## Real-World Examples
PaisaWise loads the last six messages and a separate `preferred_language` value. It does not load unrelated financial details simply because they appeared earlier.

<Scenario title="Remember the preference, not every sentence">A helpful manager remembers that you prefer Tamil, but does not repeat every private detail from every meeting. Useful memory is selective and accountable.</Scenario>

## Common Mistakes
<Mistakes>

- Loading complete history into every prompt.
- Mixing users because ownership filters are missing.
- Treating generated summaries as unquestionable facts.
- Retaining sensitive details without purpose or expiry.

</Mistakes>

## Key Takeaways
<Takeaways>

- History and memory are different.
- Scope every read by user and session.
- Load only necessary context.
- Separate durable preferences from messages.
- Make saved memories correctable.
- Apply retention deliberately.
- Protect sensitive records.
- Preserve sources for summaries.

</Takeaways>

## Final Thought and Next Path
The best memory system remembers less, but remembers the right things reliably. Next, transform events into useful AI features with aggregation.

## FAQ, Knowledge Check and Interview Answer
**Should an agent remember everything?** No. Retention follows purpose, consent, risk and lifecycle rules.

**Interview answer:** I model agent memory as scoped data products: recent session context, user-controlled preferences and separately governed audit records.
