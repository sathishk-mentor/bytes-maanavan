## Quick Start
MongoDB stores JSON-like **documents** inside **collections**. One AI conversation can keep its message, tool result and retrieved evidence together, with optional fields only when needed.

| Collection | `conversations` | Related documents |
| Document | One exchange | Complete business record |
| Field | `tool_calls` | One named value |

## Core Explanation
MongoDB encodes documents as BSON, supporting arrays, nested objects, dates and identifiers. Flexible does not mean random: keep stable core fields, use consistent names and validate values the application depends on.

```javascript
{ _id: "conv_8843", session_id: "sess_2291", user_message: "Check my balance",
  assistant_message: "Your balance is ₹45,230.50",
  tool_calls: [{ tool: "getBalance", result: 45230.50 }],
  created_at: ISODate("2026-09-18T10:16:30Z") }
```

## Types and Components
- Embed small data read with its parent, such as a tool call inside one exchange.
- Reference shared data with an independent lifecycle, such as a customer profile.
- Use schema validation for required fields and accepted types.

## Document Model vs Relational Table
| Question | Document model | Relational table |
|---|---|---|
| Varying fields | Natural optional fields | Nullable columns or related tables |
| Related nested data | Stored together | Usually separate rows |
| Strong relationships | Deliberate references | Keys and constraints |

## Real-World Examples

## Common Mistakes
<Mistakes>

- Treating flexible schema as permission for inconsistent names.
- Growing one document without considering size limits.
- Duplicating data that changes independently.
- Storing dates as display strings.

</Mistakes>

## Key Takeaways
<Takeaways>

- MongoDB stores BSON documents in collections.
- Documents support nested objects and arrays.
- Optional fields support real interaction differences.
- Stable core fields still need a contract.
- Embed data read and updated together.
- Reference data with an independent lifecycle.
- Validate critical fields.
- Model around access patterns.

</Takeaways>

## FAQ, Knowledge Check and Interview Answer
**Does MongoDB have no schema?** It has a flexible document shape and supports explicit schema validation.

**Interview answer:** MongoDB is a document database storing BSON records in collections. I choose it when nested, evolving data matches application access patterns, while still enforcing identifiers, validation and indexes.
