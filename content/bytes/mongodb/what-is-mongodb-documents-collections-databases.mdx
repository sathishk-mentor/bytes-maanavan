## Start with the business need

Our platform needs to remember a learner’s name, interests, enrolled courses, progress and preferred language. These records do not always have exactly the same shape. One learner may have a GitHub profile; another may have a portfolio URL or accessibility preference.

MongoDB is a document database. It stores related information as **BSON documents**, a binary representation that supports JSON-like objects plus types such as dates, ObjectId and decimal values.

## Database, collection, document and field

| Level | Learning-platform example | Plain meaning |
|---|---|---|
| Database | `learning_support` | Container for one application’s collections |
| Collection | `learners` | Group of related documents |
| Document | Sathish’s learner profile | One complete business record |
| Field | `preferred_language` | One named fact inside the document |

```javascript
{
  _id: ObjectId("..."),
  name: "Arun",
  preferred_language: "Tamil",
  interests: ["Python", "AI Agents"],
  progress: { completed_bytes: 7, streak_days: 4 },
  created_at: ISODate("2026-09-15T08:30:00Z")
}
```

`_id` uniquely identifies a document. MongoDB can generate an **ObjectId** automatically, but business identifiers such as `learner_id` may still be useful when integrating systems.

## SQL table versus MongoDB collection

| Relational idea | MongoDB idea | Important difference |
|---|---|---|
| Table | Collection | Collection documents can vary in shape |
| Row | Document | Document can contain nested objects and arrays |
| Column | Field | A field need not appear in every document |
| Join | Embed or reference | Model according to application access patterns |

MongoDB is not “SQL without tables.” The useful difference is the document model: related data can stay together in the shape the application uses.

## Tamil learner analogy: register versus student file

<Scenario title="Fixed register and flexible learner file">

A traditional college register has the same columns for every student. Adding a new detail may require changing the register format. A MongoDB document is closer to an individual student file: every file has essential details, while relevant extra evidence—projects, certificates or preferences—can be included.

Flexibility is useful, but an untidy file is still untidy. Production applications normally use naming rules, validation and controlled updates.

</Scenario>

## CRUD: the four everyday operations

```javascript
// Create
db.learners.insertOne({ name: "Arun", status: "active" })

// Read
db.learners.findOne({ name: "Arun" })

// Update
db.learners.updateOne(
  { name: "Arun" },
  { $set: { preferred_language: "Tamil" } }
)

// Delete only after a precise filter and business check
db.learners.deleteOne({ _id: ObjectId("...") })
```

## Where MongoDB Atlas fits

MongoDB Atlas is MongoDB’s managed cloud database service. It provides clusters, users, network controls, backups, monitoring and services such as Atlas Vector Search. Atlas reduces infrastructure work; it does not remove your responsibility for data modelling, permissions or cost control.

## Common mistakes

<Mistakes>

- Assuming flexible schema means “no schema.”
- Storing dates as display strings instead of date values.
- Using a person’s name as the unique identifier.
- Placing passwords or API keys inside application documents.
- Choosing MongoDB only because the input happens to be JSON.

</Mistakes>

## Interview bit

<ThemeCard title="What is MongoDB?" badge="CAREER">

MongoDB is a document database that stores BSON documents in collections. It is useful when an application benefits from nested data, evolving fields and access to related information as one record. I still define validation, identifiers and query-driven data models rather than treating flexibility as an absence of design.

</ThemeCard>

## Key takeaways

<Takeaways>

- Database → collection → document → field is the core hierarchy.
- BSON adds database-friendly types to a JSON-like document model.
- Flexible documents need explicit application and validation rules.
- Atlas manages database infrastructure; your team owns safe design and access.

</Takeaways>
