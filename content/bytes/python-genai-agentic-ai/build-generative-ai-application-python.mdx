An LLM produces a recommendation, but the Python application owns the viewer profile, approved streaming catalogue, validation rules and final decision boundary.

## What makes this an application

An LLM call alone is a demo. An application adds input validation, approved context, output contracts, failure handling, privacy controls and a user experience.

```text
Viewer preferences + streaming catalogue → Python context builder → LLM → structured output → validation → response
```

## Model, instructions and context

- **System instruction:** stable role, boundaries and output rules.
- **User instruction:** the learner’s current request.
- **Context:** verified profile and catalogue facts needed for this request.
- **Model response:** a proposal that application code must validate.

```python
system_instruction = """
You are a learning-path assistant.
Recommend only titles present in AVAILABLE_TITLES.
If required viewer information is missing, say so.
Return the requested structured fields.
"""
```

## Define structured output

```python
from pydantic import BaseModel, Field

class MovieRecommendation(BaseModel):
    title_id: str
    reason: str
    suitability: str
    next_step: str
    confidence: float = Field(ge=0, le=1)
    missing_information: list[str]
```

Structured output makes failures visible. Python should also verify that `title_id` exists in the current catalogue and that age rating and availability match the viewer request.

## Ground the recommendation

A viewer asks: **What can our family watch in Tamil within 90 minutes?** The application collects language, genre, age rating and available time. It retrieves eligible titles from the current streaming catalogue and sends only the useful facts to the model.

Conversation history can help with continuity, but it should be scoped, limited and summarised when necessary. Do not send an unlimited chat transcript or unrelated personal information.

## Streaming and token control

Streaming improves perceived responsiveness, but do not display an unvalidated JSON object token by token. For structured decisions, wait for and validate the complete object. Track input/output tokens, latency and estimated cost per request.

## Hallucination and human review

If the model returns a course that is not in the approved catalogue, Python must reject it. A confident sentence is not proof that the information is correct.

The model may invent a title, availability or age rating. Deterministic checks should reject unknown identifiers. Explicit confirmation is required before adding a paid title or changing a shared family watchlist.

## Practical build checklist

1. Define the learner and response models.
2. Load a small current streaming catalogue.
3. Select relevant title facts.
4. Build system and user messages.
5. Request structured output.
6. Validate required fields and title identity.
7. Return missing information instead of guessing.
8. Log latency and token use without logging private content.

## Interview bit

I constrain the task, provide verified context, request structured output and validate identifiers and business rules in Python. I also define abstention behaviour and use human review for consequential recommendations. Prompting helps, but application controls provide the dependable boundary.

## Key takeaways

<Takeaways>

- A production GenAI application is more than a model call.
- Approved knowledge should ground recommendations.
- Structured output makes validation possible.
- Python owns deterministic business rules.
- Privacy, token cost and human review belong in the initial design.
