Production readiness means the team can prove expected behaviour, limit unsafe behaviour, observe real usage and recover when a release fails.

## Organise clear boundaries

```text
app/
  api/          # request and response contracts
  services/     # learning workflow
  ai/           # prompts, models and tool loop
  tools/        # bounded operations
  models/       # typed data models
tests/
evals/
```

Separating application logic from provider-specific AI logic makes testing, model changes and incident recovery easier.

## Test deterministic code first

```python
def test_calculate_weeks_rounds_up():
    assert calculate_weeks(total_hours=21, weekly_hours=5) == 5
```

Unit tests cover small rules. Integration tests cover API, database and provider boundaries. Mock external APIs for stable failure tests, but keep a controlled end-to-end test against the real integration.

## Evaluate the AI behaviour

Maintain a fixed dataset containing normal questions, missing-context cases, unavailable titles, prompt-injection attempts and expected safety behaviour. Measure whether the system selected an available title, used the correct catalogue facts, returned required fields and requested approval when needed.

Model output varies. Use semantic criteria and business checks rather than expecting identical sentences.

## Protect every boundary

- Store secrets in a managed secret system.
- Authenticate users and authorise tools independently.
- Treat user text and retrieved documents as untrusted input.
- Keep system rules separate from external content.
- Allowlist tools and validate their parameters.
- Limit requests, agent steps, tokens, time and cost.
- Redact personal information from logs.
- Require approval for consequential operations.

Prompt injection cannot be solved by one warning sentence. Reduce its impact with least privilege, source labelling, instruction separation, output validation and approval gates.

## Package with Docker

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY app ./app
USER 10001
CMD ["python", "-m", "app"]
```

Pin dependencies, scan the image, run as a non-root user and inject secrets only at runtime. Add a lightweight health endpoint that checks the application process without making an expensive LLM call.

## Observe the real system

Monitoring should answer practical questions: Is the application available? Are recommendations useful? Which tools fail? How much does each request cost?

Track request count, error rate, latency, token usage, estimated cost, tool failures, approval outcomes and evaluation quality. Use correlation IDs to follow one request without exposing private content.

Version prompts, model configuration, tools and evaluation datasets. A rollback must restore a known compatible combination—not only an older prompt.

## Production checklist

1. Unit and integration tests pass.
2. Fixed AI evaluation meets release thresholds.
3. Secrets and permissions are reviewed.
4. Rate, token, cost and agent-step limits work.
5. Image scan and health check pass.
6. Logs, metrics and alerts are available.
7. Database backup and migration plan are confirmed.
8. Rollback is documented and rehearsed.

## Key takeaways

<Takeaways>

- Production readiness combines tests, evaluation, security and operations.
- LLM quality needs a fixed, versioned evaluation dataset.
- Limits protect reliability and cost as well as security.
- Docker provides a repeatable runtime, not complete operational safety.
- Monitoring and rollback complete the release system.

</Takeaways>
