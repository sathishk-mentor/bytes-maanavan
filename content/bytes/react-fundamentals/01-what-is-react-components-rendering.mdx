## Start with a real support dashboard

A support desk updates ticket cards when data changes. React lets developers describe the interface as reusable components.

**You will learn:** Explain the concept, predict the visible UI result and implement one small change. **Prerequisite:** Familiarity with basic JavaScript expressions helps, but no prior React experience is required.

## A support dashboard built from reusable UI

Imagine a software company's customer-support dashboard. Staff read tickets, filter the list, change ticket status and navigate between records. We use this *illustrative* workflow to learn React rather than claiming it is a real company's internal application.

React: a library for building user interfaces. Component: reusable UI function. JSX: markup-like syntax. Render: React calling components to determine UI. Props: component inputs. State: changing component data.

## Why React helps developers build interfaces

A browser does not understand JSX directly; a build tool transforms it. React calculates UI from props and state and commits necessary changes to the DOM. A component tree is a useful mental model; React is not a database or backend.

A useful analogy is an office display board: inputs describe which cards belong on the board and an update changes the visible board. React coordinates that display; a real backend remains responsible for permanent records and access control.

## Build the Support Dashboard: Step-by-Step Code

A React component is a function describing a piece of the interface. React renders components to make what people see in the browser.

**Connected learning:** These files belong to one `support-desk` application. Each code step updates or adds to the same project. The final code from this Byte is the starting point for the next Byte. **Project checkpoint:** App → main → TicketCard → browser UI.

### Step 1 — Create the project

```tsx
npm create vite@latest support-desk -- --template react-ts
cd support-desk
npm install
npm run dev
```

**Expected result:** Vite launches a local React + TypeScript development server.

### Step 2 — Create a starting dashboard

```tsx
// src/App.tsx
export default function App() {
  return <main>
    <h1>Support Desk</h1>
    <p>Tickets waiting for the team</p>
    <article>Ticket #101 — Login problem</article>
  </main>;
}
```

**Expected result:** A heading, description and first ticket appear.

### Step 3 — Introduce a child component

```tsx
// src/App.tsx
function TicketCard() {
  return <article>Ticket #101 — Login problem</article>;
}
export default function App() {
  return <main><h1>Support Desk</h1><TicketCard /></main>;
}
```

**Expected result:** The same ticket now comes from a reusable React component.


### Try it yourself

Add a second TicketCard to the dashboard. Observe that both show the same text; Byte 02 will solve that with props.

## Common React misconceptions

Do not assume React automatically stores ticket data on a server. Rendering a card does not persist records.

If the UI looks wrong, inspect data input, state updates, console errors and element semantics separately. Compare the expected output above with the actual browser result.

## How frontend teams use React

Frontend engineers compose views; designers provide UI patterns; testers verify output and accessibility. Product managers describe the workflow outcome and acceptance criteria. A support team member can validate that the wording and action match the intended business process.

## What users see and what React does

| What the user sees | What happens underneath |
|---|---|
| User sees a ticket title | React calls TicketCard and creates matching DOM updates |
| A responsive interface | React decides which UI description to reconcile with the DOM |
| A visible result after interaction | The application determines whether data is only local or saved remotely |

## Key takeaways

1. Begin with the real user problem.
2. Separate UI from persistent backend concerns.
3. Name each component or Hook by its purpose.
4. Distinguish inputs from state.
5. Trace interactions step by step.
6. Inspect the rendered result, not only code.
7. Prefer clarity over unnecessary complexity.
8. Validate behaviour, accessibility and failure cases.

## FAQ, knowledge check and references

Is React a framework? React is primarily a UI library. Does React need a backend? Not for a static interface. Is the Virtual DOM the browser DOM? No; it describes React's internal UI representation.
