## Why developers use React

React helps us create web interfaces using small reusable components. Start with one message on a webpage before learning about larger applications.

**Goal:** Explain the concept in simple words and create an output that you can see in your browser. **Prerequisite:** Basic JavaScript is useful; advanced React knowledge is not required.

## A greeting on a webpage

A component is a JavaScript function that returns JSX. React renders the component to describe what should appear on the screen. You do not need a backend to learn this.

Think about what someone sees first. Learn the smallest React concept that makes that visible result possible.

## Components and rendering explained

A component is a JavaScript function that returns JSX. React renders the component to describe what should appear on the screen. You do not need a backend to learn this.

**Remember:** A React component describes interface output. React is not a database, and this beginner example does not need an enterprise application.

```text
App component → JSX heading → React rendering → browser displays Hello React
```

## Code along: your first React page

Follow these steps in a **small React + TypeScript project**. Each step gives you a visible result.

### Step 1 — Create a React project

```bash
npm create vite@latest my-react-app -- --template react-ts
cd my-react-app
npm install
npm run dev
```

**What you should see:** Vite prints a local URL. Open it in your browser.

### Step 2 — Edit the main component

```tsx
// src/App.tsx
export default function App() {
  return <h1>Hello React!</h1>;
}
```

**What you should see:** The browser displays Hello React!

### Step 3 — Create a second component

```tsx
// src/App.tsx
function Welcome() {
  return <p>My first component</p>;
}
export default function App() {
  return <main><h1>Hello React!</h1><Welcome /></main>;
}
```

**What you should see:** The page now shows a heading and a second line.

## Common beginner mistakes

Use PascalCase for component names. Return valid JSX. Do not expect a component to store information in a database.

If the output differs from the example, inspect the browser console, component syntax, event handlers and state updates before adding more code.

## Where developers use components

A frontend developer uses this concept while building forms, menus, product cards and dashboards. The same simple idea can appear in large applications, but understanding it does not require learning an entire business workflow.

## What the browser shows vs what React renders

| What you see | What React does |
|---|---|
| A greeting appears | App returns JSX and React updates the browser DOM |
| You change a component input or interact with the page | React updates the output according to props and state |

## Eight things to remember

1. Begin with one simple problem.
2. Identify what should appear in the browser.
3. Use readable component names.
4. Keep code small and understandable.
5. Separate component inputs from state.
6. Trace changes from action to result.
7. Check expected output after each step.
8. Choose simple React patterns before optimizing.

- Is React a programming language? No, it is a JavaScript UI library.
- Do I need TypeScript first? No; the basic JSX ideas also work in JavaScript.
- Does a React app require a server API? No, not for this greeting.
