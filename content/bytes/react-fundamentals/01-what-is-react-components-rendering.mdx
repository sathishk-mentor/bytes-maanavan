## Why this React concept matters

React is a JavaScript library for describing user interfaces with reusable components. A component is a function that returns JSX. When React renders App, it determines what should appear in the browser. At this stage there is no state, no form and no backend.

**In this Byte:** First understand the concept, then apply it to one small Task Manager milestone. **What you need:** Basic JavaScript. You do not need to know advanced React.

## Understand the concept with a familiar example

Think of a task board drawn on a whiteboard: the list is visible, but it cannot change until we introduce interaction.

## Build the Task Manager step by step

**Our learning project:** A tiny Task Manager, not an enterprise support system. The app grows gradually across the five Bytes; each code step below tells you exactly which file to edit.

**Milestone 1:** What Is React? Build the First Task Manager Screen.

### Step 1: Create a fresh Vite app

**Where:** `Terminal`

```bash
npm create vite@latest task-manager -- --template react-ts
cd task-manager
npm install
npm run dev
```

**Expected screen/result:** Open the local Vite address and confirm the starter page appears.

### Step 2: Build a static screen

**Where:** `src/App.tsx`

```tsx
export default function App() {
  return (
    <main>
      <h1>My Task Manager</h1>
      <p>Tasks to complete today</p>
      <ul>
        <li>Read React notes</li>
        <li>Practise JSX</li>
      </ul>
    </main>
  );
}
```

**Expected screen/result:** You see a heading and two list items.

### Step 3: Understand the tree

**Where:** `No code change`

```tsx
App
 └─ main
    ├─ h1
    ├─ p
    └─ ul
       ├─ li
       └─ li
```

**Expected screen/result:** The visible output is built from a component returning a nested JSX tree.

**Project checkpoint:** A static task list.

## Common mistakes and how to avoid them

A component is not a stored HTML document or backend. JSX needs one enclosing root element; do not confuse React rendering with data persistence.

When something breaks, read the first error message, identify the file involved, and compare your code against the prior working checkpoint.

## Where this concept is used

React uses the same underlying idea in many applications: a product list, a shopping basket, a learning progress page, or a dashboard. We are using task management only to keep the learning journey simple.

## What learners see versus what React does

| What a learner sees | What React or the browser does |

## Key takeaways

1. Begin with the user-facing result.
2. Learn the concept before writing code.
3. Keep one clear goal per change.
4. Use components for reusable UI.
5. Treat props as read-only inputs.
6. Update state with setter functions.
7. Inspect the browser after every step.
8. Prefer simple code to unnecessary optimization.
