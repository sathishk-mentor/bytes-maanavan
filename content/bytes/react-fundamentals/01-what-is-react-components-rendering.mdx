## Why build interfaces with React?

Imagine writing a shopping list on paper. You can read it, but pressing a button cannot change it. Web applications add behavior to the screen. React helps us organize that screen into reusable pieces. First, we build a *static* To-Do List; interaction comes later.

**What you will build:** Milestone 1 of a small browser-based To-Do List. No backend or advanced architecture is needed.

## A task list you already understand

Before React, learn three layers: **HTML** describes content (a heading or list); **CSS** controls appearance (spacing and colors); **JavaScript** decides behavior (what happens after a click). React is a JavaScript library for building the interface. It does not replace HTML or CSS. **Vite** starts a local development project and converts JSX/TypeScript into browser-friendly code.

## Components, JSX and rendering

A **component** is a function whose name begins with a capital letter and which returns a description of UI. **JSX** resembles HTML, but it lives inside JavaScript. `className` is used instead of HTML's `class`; JavaScript expressions go inside `{ }`. **Rendering** means React evaluates components and updates the browser when needed. `App` is our starting component, not a special React keyword. A nested element goes inside its parent; JSX must return one enclosing root (or fragment).

## Trace the first React render

1. Browser loads the application.

2. React renders `App()`.

3. `App` returns JSX containing a heading and list.

4. React commits the matching elements to the browser DOM.

5. The learner sees two to-do items. No interaction or storage yet.

## Create the first Task Manager screen

**Our learning project:** A tiny Task Manager, not an enterprise support system. The app grows gradually across the five Bytes; each code step below tells you exactly which file to edit.

**Milestone 1:** What Is React? Build the First Task Manager Screen.

### Step 1: Create a fresh Vite app

**Where:** `Terminal`

```bash
npm create vite@latest task-manager -- --template react-ts
cd task-manager
npm install
npm run dev
```

**Expected screen/result:** Open the local Vite address and confirm the starter page appears.

### Step 2: Build a static screen

**Where:** `src/App.tsx`

```tsx
export default function App() {
  return (
    <main>
      <h1>My Task Manager</h1>
      <p>Tasks to complete today</p>
      <ul>
        <li>Read React notes</li>
        <li>Practise JSX</li>
      </ul>
    </main>
  );
}
```

**Expected screen/result:** You see a heading and two list items.

### Step 3: Understand the tree

**Where:** `No code change`

```tsx
App
 └─ main
    ├─ h1
    ├─ p
    └─ ul
       ├─ li
       └─ li
```

**Expected screen/result:** The visible output is built from a component returning a nested JSX tree.

**Project checkpoint:** A static task list.

## Mistakes beginners often make

- **Blank page?** Check the terminal and browser console for a JSX syntax error.
- **Two root elements?** Wrap them with `<main>...</main>` or a fragment.
- **Component name lowercase?** React treats lowercase JSX names as built-in HTML tags.
- **Expecting buttons already?** This is a static screen; state and event handling arrive in Byte 03.

## Where React components are used

React uses the same underlying idea in many applications: a product list, a shopping basket, a learning progress page, or a dashboard. We are using task management only to keep the learning journey simple.

## The visible screen and the render process

| What a learner sees | What React or the browser does |
|---|---|
| browser shows tasks | App() → JSX `main` → `h1` and `ul` |
| A task list ready for interaction | React creates output from component inputs and state |

## Key takeaways

1. HTML describes the page structure.
2. CSS styles that structure.
3. JavaScript adds behavior.
4. React is a UI library built on JavaScript.
5. A component is a function that returns UI.
6. JSX lets us describe elements within JavaScript.
7. Vite helps create and run the development project.
8. Our first milestone is a static list—not a complete app.

## FAQ and knowledge check

- Why React rather than repeating HTML? Reusable components become useful as interfaces grow.
- Is a backend required? No. This first screen is static.
- Does React save tasks yet? No, it only displays the list.

**Interview-ready explanation:** React is a JavaScript library for describing user interfaces with reusable components. A component is a function that returns JSX. When React renders App, it determines what should appear in the browser. At this stage there is no state, no form and no backend.
