## Why repeatable UI matters

You should not copy the same HTML for every greeting. Build one Greeting component and pass each person's name as a prop.

**Goal:** Explain the concept in simple words and create an output that you can see in your browser. **Prerequisite:** Basic JavaScript is useful; advanced React knowledge is not required.

## Two greeting cards, one component

JSX lets a component describe UI. Props are read-only inputs passed from a parent to a child. One component can produce different output when its props change.

Think about what someone sees first. Learn the smallest React concept that makes that visible result possible.

## JSX and props in plain English

JSX lets a component describe UI. Props are read-only inputs passed from a parent to a child. One component can produce different output when its props change.

**Remember:** A React component describes interface output. React is not a database, and this beginner example does not need an enterprise application.

## How a parent passes props

```text
App → name='Anu' / name='Ravi' → Greeting component → two different greetings
```

Read each arrow as a small change: input or click, JavaScript/React action, and the browser result.

## Code along: reusable greeting cards

Follow these steps in a **small React + TypeScript project**. Each step gives you a visible result.

### Step 1 — Create a reusable component

```tsx
// src/Greeting.tsx
export default function Greeting({ name }: { name: string }) {
  return <p>Hello, {name}!</p>;
}
```

**What you should see:** Greeting shows whichever name it receives.

### Step 2 — Use it in App

```tsx
// src/App.tsx
import Greeting from './Greeting';
export default function App() {
  return <main><h1>Welcome</h1><Greeting name="Anu" /><Greeting name="Ravi" /></main>;
}
```

**What you should see:** Hello, Anu! and Hello, Ravi! both appear.

### Step 3 — Add another input

```tsx
// src/Greeting.tsx
export default function Greeting({ name, role }: { name: string; role: string }) {
  return <p>Hello, {name}! You are a {role}.</p>;
}
// src/App.tsx — pass name and role to each Greeting
// <Greeting name="Anu" role="learner" />
```

**What you should see:** One reusable component now displays two kinds of information.

## Common props mistakes

Do not change props inside the child. Use correct JSX attribute syntax and capitalize component names.

If the output differs from the example, inspect the browser console, component syntax, event handlers and state updates before adding more code.

## Where teams reuse components

A frontend developer uses this concept while building forms, menus, product cards and dashboards. The same simple idea can appear in large applications, but understanding it does not require learning an entire business workflow.

## What users see vs component inputs

| What you see | What React does |
|---|---|
| Different names appear | App passes different props into the same Greeting function |
| You change a component input or interact with the page | React updates the output according to props and state |

## Eight things to remember

1. Begin with one simple problem.
2. Identify what should appear in the browser.
3. Use readable component names.
4. Keep code small and understandable.
5. Separate component inputs from state.
6. Trace changes from action to result.
7. Check expected output after each step.
8. Choose simple React patterns before optimizing.

## FAQ, knowledge check and references

- Can props contain numbers? Yes.
- Can a child edit a prop? Props should be treated as read-only.
- Do props update the interface? Changed props cause React to render updated output.
