## Why a static task list is not enough

The current to-do list is only a display. A learner should be able to type a task, click **Add**, and tick a checkbox. These actions change what appears on the screen. For that we need *state* and *event handlers*.

**What you will build:** Milestone 3 of a small browser-based To-Do List. No backend or advanced architecture is needed.

## Adding and completing tasks

Imagine an editable whiteboard: the list is what everyone sees, and the marker actions change it. In React, **state** is the current remembered list and `setTasks` is how we request an update. React then renders the new list.

## State, events and immutable updates

`useState(initialTasks)` returns `[tasks, setTasks]`: the current value and a setter. The typed input has another state value, `draft`. A **controlled input** gets `value={draft}` and updates through `onChange`. An **event handler** such as `onClick={addTask}` runs after a click. To add a task, create a new array with `[...current, newTask]`. To toggle one task, use `.map()` and copy only the matching object. Never mutate the old array in place. `pending` is *derived data* and should be calculated using `.filter()` rather than stored separately.

## Follow an Add Task click

1. Learner types `Buy notebook` → `onChange` calls `setDraft`.

2. React renders the new input value.

3. Learner clicks Add → `addTask` checks for empty text.

4. `setTasks` creates a new array with the added task.

5. React renders an extra row and clears the input.

6. Checking a box updates the matching task and pending count.

**Where:** `src/components/TaskItem.tsx`

```tsx
export default function TaskItem({
  task, onToggle
}: {
  task: Task; onToggle: (id: number) => void

  return (
    <li>
      <label>
        <input type="checkbox" checked={task.completed}
          onChange={() => onToggle(task.id)} />

    </li>
  );
}
```

### Step 3: Add task state and events

**Where:** `src/App.tsx`

```tsx
import { useState } from 'react';
import TaskItem, { type Task } from './components/TaskItem';
import { initialTasks } from './data/tasks';

export default function App() {
  const [tasks, setTasks] = useState<Task[]>(initialTasks);
  const [draft, setDraft] = useState('');

  function addTask() {
    const title = draft.trim();
    if (!title) return;
    setTasks(current => [
      ...current,
      { id: Date.now(), title, completed: false }
    ]);
    setDraft('');
  }

  function toggleTask(id: number) {
    setTasks(current => current.map(task =>
      task.id === id ? { ...task, completed: !task.completed } : task
    ));
  }

  return (
    <main>
      <h1>My Task Manager</h1>
      <label htmlFor="new-task">New task</label>
      <input id="new-task" value={draft}
        onChange={event => setDraft(event.target.value)} />
      <button type="button" onClick={addTask}>Add</button>
      <p>{tasks.filter(task => !task.completed).length} pending</p>
      <ul>{tasks.map(task =>
        <TaskItem key={task.id} task={task} onToggle={toggleTask} />
      )}</ul>
    </main>
  );
}
```

**Expected screen/result:** Typing and clicking Add creates a new task; checking it updates pending count and completion state.

## Common useState mistakes

- **`onClick={addTask()}`:** This executes during rendering; pass `onClick={addTask}`.
- **Mutating arrays:** `tasks.push()` does not create the next state snapshot.
- **Empty items:** Use `trim()` and return early.
- **Separate pending state:** Duplicated state can disagree with the actual tasks.
- **Refresh loses tasks:** Correct for now; Byte 04 adds persistence.

## Where UI state matters

React uses the same underlying idea in many applications: a product list, a shopping basket, a learning progress page, or a dashboard. We are using task management only to keep the learning journey simple.

## What happens when state changes

| What a learner sees | What React or the browser does |
|---|---|
| updated checkbox | Type  →  setDraft  →  render input; click Add  →  setTasks  →  render new row; click Complete  →  setTasks |
| A task list ready for interaction | React creates output from component inputs and state |

## Key takeaways

1. State stores UI values between renders.
2. useState returns a value and setter.
3. A controlled input displays its state.
4. onChange updates input state.
5. onClick responds to a user action.
6. State arrays should be updated immutably.
7. Derived counts should not be separate state.
8. The app now adds and completes tasks in memory.

## FAQ and knowledge check

- Why use the setter? React needs to know the state changed.
- Should pending count be another state variable? No, derive it from tasks.
- Does the task survive refresh? Not yet; Byte 04 addresses that.

**Interview-ready explanation:** State is data React remembers between renders. useState gives a value and an update function. A controlled input displays a state value. Event handlers respond to clicking or typing. Never mutate the old task array; create a new array and pass it to the setter.
