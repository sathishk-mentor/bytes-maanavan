## Why buttons need state

A greeting can stay the same, but what happens when someone clicks a button? React state helps the page remember a number and display changes.

## Code along: your React counter

Follow these steps in a **small React + TypeScript project**. Each step gives you a visible result.

### Step 1 — Create a counter

```tsx
// src/App.tsx
import { useState } from 'react';
export default function App() {
  const [count, setCount] = useState(0);
  return <main><h1>Count: {count}</h1></main>;
}
```

**What you should see:** Count: 0 is displayed.

### Step 2 — Add Increment

```tsx
// Add inside <main> after the heading:
<button onClick={() => setCount(previous => previous + 1)}>Increase</button>
```

**What you should see:** Clicking Increase updates the number.

### Step 3 — Add Decrement and Reset

```tsx
// Add after Increase:
<button onClick={() => setCount(previous => previous - 1)}>Decrease</button>
<button onClick={() => setCount(0)}>Reset</button>
```

**What you should see:** The three buttons change the displayed state.

## Common state mistakes

Do not write count = count + 1 to update React state. Use the setter. Prefer functional updates when the new value depends on the previous value.

If the output differs from the example, inspect the browser console, component syntax, event handlers and state updates before adding more code.

## Where developers use state

A frontend developer uses this concept while building forms, menus, product cards and dashboards. The same simple idea can appear in large applications, but understanding it does not require learning an entire business workflow.

## What changes behind a button click

| What you see | What React does |
|---|---|
| The number changes after clicking | React processes a state update and renders the new value |
| You change a component input or interact with the page | React updates the output according to props and state |

## FAQ, knowledge check and references

- Is state a regular variable? No, React tracks it across renders.
- Does updating state save to a database? No.
- Why use previous => previous + 1? It uses the most recent pending value.
