### Step 2: Read saved tasks when initializing state

**Where:** `src/App.tsx`

```tsx
// Replace the initial useState<Task[]>(initialTasks) declaration:
const [tasks, setTasks] = useState<Task[]>(() => {
  try {
    const saved = window.localStorage.getItem('my-tasks');
    return saved ? JSON.parse(saved) as Task[] : initialTasks;
  } catch {
    return initialTasks;
  }
});
```

**Expected screen/result:** Saved tasks load on a browser-only Vite app. This initial code intentionally targets client-only rendering.

### Step 3: Add a save Effect

**Where:** `src/App.tsx`

```tsx
// Import useEffect alongside useState:
import { useEffect, useState } from 'react';

// Inside App, below tasks state:
useEffect(() => {
  window.localStorage.setItem('my-tasks', JSON.stringify(tasks));
}, [tasks]);
```

**Expected screen/result:** Adding or completing a task now updates browser storage after render.

## Common useEffect mistakes

Avoid reading localStorage during server rendering. JSON.parse can fail on corrupt values; this demo catches that case. localStorage is not secure shared data storage. Effects may run extra setup/cleanup checks in development Strict Mode.

When something breaks, read the first error message, identify the file involved, and compare your code against the prior working checkpoint.
