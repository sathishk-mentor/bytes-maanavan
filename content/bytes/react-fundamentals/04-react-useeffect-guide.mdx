## When React needs an Effect

Some things happen outside React, like a browser timer. useEffect helps React synchronize with them. A small seconds timer makes the lifecycle visible.

**Goal:** Explain the concept in simple words and create an output that you can see in your browser. **Prerequisite:** Basic JavaScript is useful; advanced React knowledge is not required.

## A timer that updates every second

useEffect runs after React commits a render. It can start a timer or subscribe to an external system, then return cleanup to stop it. Ordinary calculated values do not need Effects.

## Code along: build a seconds timer

Follow these steps in a **small React + TypeScript project**. Each step gives you a visible result.

### Step 1 — Display a seconds value

```tsx
// src/App.tsx
import { useState } from 'react';
export default function App() {
 const [seconds, setSeconds] = useState(0);
 return <main><h1>Seconds: {seconds}</h1></main>;
}
```

**What you should see:** Seconds: 0 appears.

### Step 2 — Start a browser interval

```tsx
// Import useEffect as well, then add inside App:
useEffect(() => {
 const timer = window.setInterval(() => setSeconds(value => value + 1), 1000);
 return () => window.clearInterval(timer);
}, []);
```

**What you should see:** The count increases every second.

### Step 3 — Understand cleanup

```tsx
// Observe the return statement in useEffect:
return () => window.clearInterval(timer);
```

**What you should see:** When the component is removed, React clears the interval. In development Strict Mode, setup/cleanup may be tested more than once.

## Common useEffect mistakes

Do not omit cleanup for intervals. Do not write an Effect just to compute a number from existing state. Include all reactive dependencies when used.

If the output differs from the example, inspect the browser console, component syntax, event handlers and state updates before adding more code.

## Where applications use Effects

A frontend developer uses this concept while building forms, menus, product cards and dashboards. The same simple idea can appear in large applications, but understanding it does not require learning an entire business workflow.

## What appears vs what happens underneath

| What you see | What React does |
|---|---|
| Seconds tick on screen | An interval outside React calls a state updater and cleanup stops the interval |
| You change a component input or interact with the page | React updates the output according to props and state |
