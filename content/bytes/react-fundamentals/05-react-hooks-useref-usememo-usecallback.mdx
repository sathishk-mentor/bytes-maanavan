Not every UI problem needs the same Hook. Use a small list of names to understand useState, useRef, and optional useMemo without complex application architecture.

## Code along: focus and filter names

Follow these steps in a **small React + TypeScript project**. Each step gives you a visible result.

### Step 1 — Build a searchable list

```tsx
// src/App.tsx
import { useState } from 'react';
export default function App() {
 const [query, setQuery] = useState('');
 const names = ['Anu', 'Ravi', 'Meena'];
 const visible = names.filter(name => name.toLowerCase().includes(query.toLowerCase()));
 return <main><input value={query} onChange={e => setQuery(e.target.value)} aria-label="Search names" />
 <ul>{visible.map(name => <li key={name}>{name}</li>)}</ul></main>;
}
```

**What you should see:** Typing a name filters the list.

### Step 2 — Focus the input

```tsx
// Import useRef and add inside App:
const searchRef = useRef<HTMLInputElement>(null);
// Add ref={searchRef} to <input> and a button:
<button onClick={() => searchRef.current?.focus()}>Focus search</button>
```

**What you should see:** Clicking the button focuses the input.

### Step 3 — Understand optional memoization

```tsx
// Import useMemo. Replace the visible calculation with:
const visible = useMemo(() => names.filter(name =>
 name.toLowerCase().includes(query.toLowerCase())
), [query]);
```

**What you should see:** The output stays the same. Caching is not necessary for three names; this demonstrates the idea only.

### Step 4 — Recognize useCallback

```tsx
// Import useCallback, then inside App:
const focusSearch = useCallback(() => searchRef.current?.focus(), []);
// Change button to onClick={focusSearch}
```

**What you should see:** The button behaves the same. A stable function reference matters in specific optimization cases, not every app.

## Common Hook misconceptions

Do not use a ref to store UI state that should render. Do not add useMemo or useCallback everywhere; use them only when they solve a real issue.

If the output differs from the example, inspect the browser console, component syntax, event handlers and state updates before adding more code.

## How developers select Hooks

A frontend developer uses this concept while building forms, menus, product cards and dashboards. The same simple idea can appear in large applications, but understanding it does not require learning an entire business workflow.
