## What you will build

**Milestone 12:** Use the project created in Byte 11. One data object represents one support ticket, while a reusable component controls its appearance. Add a record and watch the visible dashboard change without copying the card markup.

Repeated ticket cards should share one design and receive data through props.

**Visible checkpoint:** Two ticket cards render from one component with distinct priority/status labels. You can study this Byte by itself, though the project can also be built progressively.

## Understand the concept first

Model each ticket as a typed object. Render arrays with map and stable keys. Keep tickets as the source of truth; calculate counts directly from the array instead of storing duplicate totals.

In plain language, an interface should show useful information and respond predictably to users. We begin with one small technical change before introducing more features.

### Step 2 — Create a reusable ticket card

**Edit or create the indicated file.**

```tsx
// src/components/TicketCard.tsx
import type {Ticket} from '../data/tickets';
export default function TicketCard({ticket}:{ticket:Ticket}){
 return <article className="rounded-xl border bg-white p-4"><h2 className="font-semibold">#{ticket.id} {ticket.subject}</h2><p>{ticket.priority} priority · {ticket.status}</p></article>;
}
```

## Interactive decision and diagnosis

If the expected result does not appear, inspect the relevant file and resolve the first console error. Compare your current code to the preceding checkpoint.

**Typical issue:** Array indexes are fragile keys when records can be added or reordered; use ticket.id.

## Key Takeaways

1. A Ticket type defines the fields in each record.
2. A typed array can hold multiple ticket objects.
3. One TicketCard component renders different tickets.
4. Props supply a record to the reusable component.
5. React maps the tickets array into JSX elements.
6. Each rendered ticket must have a stable key.
7. Dashboard totals can be calculated from ticket data.
8. A data change should not require duplicated JSX.
