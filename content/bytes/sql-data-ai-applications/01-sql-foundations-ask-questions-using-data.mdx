## Start with the business question

SQL is a language for asking a relational database precise questions. A database contains tables; a table has named columns; each row represents one occurrence of the thing being stored.

| Table | One row means | Example columns |
|---|---|---|
| `courses` | one course | `course_id`, `title`, `category`, `price` |
| `customers` | one learner | `customer_id`, `name`, `country` |
| `orders` | one purchase | `order_id`, `customer_id`, `ordered_at` |

## Read only what you need

Question: “Show the five highest-priced active AI courses.”

```sql
SELECT course_id, title, price
FROM courses
WHERE category = 'AI' AND status = 'ACTIVE'
ORDER BY price DESC
LIMIT 5;
```

Read it in this logical sequence:

1. `FROM` identifies the data source.
2. `WHERE` keeps matching rows.
3. `SELECT` returns approved columns.
4. `ORDER BY` arranges the result.
5. `LIMIT` caps its size.

Avoid `SELECT *` in application queries. Explicit columns reduce unnecessary data transfer and protect the contract when a table later gains sensitive fields.

## Relationships give rows context

A **primary key** uniquely identifies a row. A **foreign key** points to a related row in another table. For example, `orders.customer_id` connects a purchase to one customer. Byte 3 will use these keys in joins.

<Scenario title="Real-time analogy: asking a librarian">

“Give me every book” is expensive and unclear. “Give me the title and price of five active AI books, highest price first” tells the librarian the shelf, filter, fields, order and limit. A good SQL query is equally explicit.

</Scenario>

## Common mistakes

<Mistakes>

- Using `SELECT *` when only two or three columns are required.
- Forgetting that `NULL` needs `IS NULL`, not `= NULL`.
- Applying `LIMIT` without a deterministic `ORDER BY`.
- Mixing text and numeric values without understanding types.
- Updating data while still learning a read-only query.

</Mistakes>

## Interview bit

<ThemeCard title="What is the difference between WHERE and ORDER BY?" badge="CAREER">

`WHERE` determines which rows qualify. `ORDER BY` arranges the qualifying rows. Filtering changes membership of the result; sorting changes presentation order.

</ThemeCard>

## Key takeaways

<Takeaways>

- Begin with a precise business question.
- Tables store related rows under a consistent column structure.
- Select explicit columns, filter intentionally and bound results.
- Keys allow reliable relationships across tables.

</Takeaways>
