## 60 seconds-ல் Docker

Docker என்பது application code, runtime, libraries மற்றும் தேவையான configuration ஆகியவற்றை மீண்டும் மீண்டும் ஒரே விதமாகப் பயன்படுத்தக்கூடிய image-ஆக package செய்ய உதவும் platform. அந்த image இயங்கும் instance தான் container. இதனால் developer laptop, test server மற்றும் cloud ஆகிய சூழல்களில் ஒரே tested package-ஐ இயக்க முடியும்.

Container என்பது virtual machine அல்ல. அது host operating-system kernel-ஐ பகிர்ந்து கொண்டு isolated process-ஆக இயங்குகிறது. அதனால் அது பொதுவாக lightweight மற்றும் வேகமாக start ஆகும். இருப்பினும் security boundary, permissions மற்றும் resource limits அவசியம்.

## “Works on my machine” ஏன் நடக்கிறது?

Developer machine-ல் Python 3.12 இருக்கலாம்; server-ல் 3.10 இருக்கலாம். ஒரு package install ஆகாமல் இருக்கலாம். Environment variable, operating-system library அல்லது start command மாறியிருக்கலாம். இத்தகைய வேறுபாடுகளால் application மற்றொரு machine-ல் fail ஆகும். Dockerfile தேவையான environment-ஐ code-ஆக பதிவு செய்வதால் setup repeatable ஆகிறது.

## Four Docker objects எப்படி connect ஆகும்?

<DockerFlowVisual variant="mentalModel" />

- **Dockerfile:** Image build செய்யும் recipe.
- **Image:** Immutable packaged template.
- **Container:** Image-ன் running instance.
- **Registry:** Versioned images store மற்றும் distribute செய்யும் service.

### ஒரு code change-ன் பயணத்தைப் பார்ப்போம்

Developer source code-ஐ மாற்றுகிறார். `docker build` Dockerfile instructions-ஐப் பயன்படுத்தி புதிய image உருவாக்குகிறது. அந்த image version tag உடன் registry-க்கு push செய்யப்படுகிறது. Test அல்லது production environment அதே image-ஐ pull செய்து புதிய container உருவாக்குகிறது. Running container-க்குள் manual change செய்வதற்குப் பதிலாக image-ஐ rebuild செய்வதே repeatable workflow.

Standard shipping container கப்பல், ரயில் அல்லது லாரி மாறினாலும் பொருட்களை ஒரே sealed format-ல் எடுத்துச் செல்லும். அதுபோல Docker image application மற்றும் அதன் runtime requirements-ஐ standard package-ஆக வைத்திருக்கும். Destination environment-க்கு compatible container runtime தேவை. ஆனால் இந்த analogy முழுமையான security guarantee-ஐ குறிக்காது.

## Container மற்றும் virtual machine different

Virtual machine தனி guest operating system-ஐ இயக்குகிறது. Container host kernel-ஐ பகிர்கிறது. Different operating system அல்லது stronger isolation தேவைப்படும் workload-க்கு VM பொருத்தமாக இருக்கலாம். Fast startup மற்றும் application packaging-க்கு container பயனுள்ளதாக இருக்கும். Production architecture-ல் இரண்டையும் சேர்த்தும் பயன்படுத்தலாம்.

## Smallest useful workflow

Dockerfile எழுதுங்கள் → image build செய்யுங்கள் → container run செய்யுங்கள் → exposed service-ஐ test செய்யுங்கள் → logs inspect செய்யுங்கள் → test செய்யப்பட்ட அதே image-ஐ registry-க்கு push செய்யுங்கள்.

### Command-க்குப் பின்னால் Docker என்ன செய்கிறது?

`docker build -t status-api:1.0 .` build context மற்றும் Dockerfile-ஐப் படித்து image layers உருவாக்குகிறது. `docker run --rm status-api:1.0` அந்த image-லிருந்து isolated process உருவாக்குகிறது. Container stop ஆனாலும் image நீடிக்கும்; புதிய container-ஐ அதிலிருந்து மீண்டும் உருவாக்கலாம்.

## Docker எப்போது help செய்யும்?

Repeatable development, CI/CD, microservices, dependency isolation மற்றும் cloud deployment ஆகியவற்றுக்கு Docker உதவும். ஆனால் poor application design, missing tests, insecure secrets அல்லது missing monitoring போன்ற பிரச்சினைகளை Docker தானாகத் தீர்க்காது.

## Common mistakes

<Mistakes>

- Image மற்றும் container ஒன்றே என்று நினைப்பது.
- Container-க்குள் manually fix செய்து image rebuild செய்யாமல் விடுவது.
- Secret-ஐ Dockerfile அல்லது image layer-ல் bake செய்வது.
- `latest` tag மட்டும் use செய்து exact version lose செய்வது.
- Container use செய்ததால் application secure என்று assume செய்வது.

</Mistakes>

## Interview-ல் எப்படி explain செய்வது?

<ThemeCard title="Docker image மற்றும் container difference?" badge="CAREER">

Image immutable application package/template. Container அந்த image-லிருந்து create ஆன running process instance. One image-லிருந்து multiple containers run செய்யலாம்; runtime change வேண்டுமென்றால் source/Dockerfile update செய்து new image build பண்ண வேண்டும்.

</ThemeCard>
