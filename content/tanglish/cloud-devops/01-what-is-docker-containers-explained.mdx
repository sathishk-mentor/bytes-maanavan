## Start from Basics

- **Dockerfile:** Image எப்படி build ஆகணும் என்று சொல்லும் instruction file.
- **Image:** App மற்றும் அது start ஆக தேவையான files சேர்த்து prepare செய்த package. இது இன்னும் run ஆகவில்லை.
- **Container:** Image-லிருந்து start ஆன running app copy.
- **Registry:** Images store மற்றும் share செய்யும் place; Docker Hub ஒரு example.
- **Tag:** Image version identify செய்யும் label, example `1.0`.
- **Docker Engine:** Dockerfile instructions follow பண்ணி image build செய்து container start செய்யும் Docker software.

## Core Explanation

Flow ரொம்ப simple. Dockerfile என்பது recipe. Docker அந்த recipe-ஐ follow பண்ணி image என்ற ready package-ஐ create பண்ணும். அந்த image-ஐ start பண்ணும்போது container என்ற running app கிடைக்கும்.

Team image-ஐ registry என்ற online store-ல் save பண்ணலாம். இன்னொரு developer அந்த exact image-ஐ download செய்து புதிய container start பண்ணலாம். அவரவர் laptop-ல் setup steps guess பண்ண வேண்டிய அவசியம் குறையும்.

Container என்பது இன்னொரு full computer இல்லை. அது host operating system-ன் ஒரு பகுதியை share செய்து separate process-ஆ run ஆகும். Virtual machine-ல் full guest operating system இருக்கும். Beginner level-ல் நினைவில் வைக்க வேண்டியது: container பொதுவாக quick-ஆ start ஆகும்; VM அதிகமான system files உடன் வரும்.

## Docker Container vs Virtual Machine

| Question | Container | Virtual Machine |
|---|---|---|
| OS | Host kernel share பண்ணும் | Full guest OS run பண்ணும் |
| Startup | பொதுவாக seconds | பொதுவாக அதிக நேரம் |
| Package | App + dependencies | App + dependencies + full OS |
| Best fit | Portable app workloads | Strong isolation அல்லது different OS |

Container always better இல்லை. Requirement பார்த்து choose பண்ணணும்.
