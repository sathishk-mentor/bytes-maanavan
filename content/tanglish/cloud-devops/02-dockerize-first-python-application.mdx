## இன்று என்ன build பண்ணப் போறோம்?

ஒரு delivery-status app-ஐ container-க்குள் run பண்ணப் போறோம். Result simple: browser-ல் `/health` open பண்ணினால் `healthy` response வரணும். Dockerfile எழுதுவதற்கு முன்னாடி app normal-ஆ start ஆகுதா என்று one time check பண்ணுங்க.

## Dockerfile-na app packing instruction

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY app.py .
EXPOSE 8000
CMD ["python", "app.py"]
```

### File-ஐ top-to-bottom read பண்ணலாம்

| Line | Easy meaning |
|---|---|
| `FROM python:3.12-slim` | “இந்த Python setup-லிருந்து start பண்ணு” |
| `WORKDIR /app` | “Container-க்குள் `/app` folder-ல் work பண்ணு” |
| `COPY requirements.txt .` | Required libraries list-ஐ copy பண்ணு |
| `RUN pip install...` | அந்த libraries-ஐ image build time-ல் install பண்ணு |
| `COPY app.py .` | நம்ம app code-ஐ copy பண்ணு |
| `EXPOSE 8000` | App 8000 port expect பண்ணுது என்று document பண்ணு |
| `CMD [...]` | Container start ஆனதும் app-ஐ run பண்ணு |

இப்போதைக்கு cache, layers, signal handling எல்லாம் memorize பண்ண வேண்டாம். First goal: ஒவ்வொரு Dockerfile line-க்கும் ஒரு clear job இருக்கு என்று understand பண்ணுவது.

## தேவையில்லாத files image-க்குள் போகக்கூடாது

Travel bag pack பண்ணும்போது room-ல இருக்கிற எல்லாத்தையும் எடுத்துட்டு போக மாட்டோம். அதே மாதிரி `.git`, `.venv`, cache, local logs, `.env` போன்ற files image-க்குள் போக வேண்டாம். `.dockerignore` file அவற்றை skip பண்ணும்.

## மூன்று commands: build → run → check

இங்க `-p 8000:8000` என்பது laptop-ல் இருக்கும் 8000 door-ஐ container app-ன் 8000 door-க்கு connect பண்ணும். Port topic-ஐ Byte 03-ல் detail-ஆ பார்க்கலாம். இப்போதைக்கு browser container app-ஐ reach செய்ய இந்த mapping தேவை என்று மட்டும் நினைவில் வைங்க.

```bash
docker build -t delivery-status:1.0 .
docker run --rm -p 8000:8000 delivery-status:1.0
```

Browser-ல் `localhost:8000/health` open பண்ணினால் healthy response வரணும். App `0.0.0.0:8000`-ல் listen செய்வதால் Docker create செய்த door connection வழியாக request உள்ளே வரும்.

## Work ஆகலையா? One-by-one check பண்ணுங்க

| Problem | First check |
|---|---|
| Build fail ஆகுது | Error message-க்கு மேல இருக்கிற failed Dockerfile line |
| Container உடனே stop ஆகுது | `docker logs` output |
| Browser open ஆகல | `-p 8000:8000` இருக்கா? App `0.0.0.0`-ல் listen ஆகுதா? |
| Code change தெரியல | Image rebuild பண்ணீங்களா? |

Random commands try பண்ணாதீங்க. First error எங்கே வந்தது என்று கண்டுபிடிச்சு, அந்த one step-ஐ மட்டும் fix பண்ணுங்க.

## Common mistakes

<Mistakes>

- App local-ல் run ஆகிறதா verify செய்யாமல் Docker debug செய்வது.
- `.venv` மற்றும் secrets image-க்கு copy செய்வது.
- Application `localhost` மட்டும் bind செய்வது.
- Reproducible version tag இல்லாமல் image build செய்வது.
- Container shell-ல் manual package install செய்து fix preserve ஆனது என்று நினைப்பது.

</Mistakes>

## Interview answer—build vs run

<ThemeCard title="docker build மற்றும் docker run-ல் என்ன நடக்கும்?" badge="CAREER">

`docker build`, Dockerfile instructions-ஐ follow பண்ணி image create பண்ணும். `docker run`, அந்த image-லிருந்து container start செய்து app process-ஐ run பண்ணும். Build என்பது package prepare செய்வது; run என்பது அந்த package-ஐ start செய்வது.

</ThemeCard>
