## Application contract-லிருந்து start பண்ணுங்க

Containerize செய்வதற்கு முன் app local-ல் எப்படி start ஆகிறது, எந்த port listen செய்கிறது, dependencies என்ன, health endpoint என்ன என்பதை confirm பண்ணுங்க. Broken app-ஐ Docker correct பண்ணாது.

## Dockerfile எழுதுவது

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY app.py .
EXPOSE 8000
CMD ["python", "app.py"]
```

Base image runtime கொடுக்கும். `WORKDIR` container working folder define பண்ணும். Dependency file-ஐ முதலில் copy செய்தால் code-only changes-க்கு build cache reuse ஆகும். Exec-form `CMD` signal handling-க்கு better.

## `.dockerignore` add பண்ணுங்க

`.git`, `.venv`, cache, local logs, secrets மற்றும் unnecessary files build context-க்கு போகாமல் exclude பண்ணுங்க. Smaller context build speed மற்றும் accidental data exposure reduce பண்ணும்.

## Build, run மற்றும் test

```bash
docker build -t delivery-status:1.0 .
docker run --rm -p 8000:8000 delivery-status:1.0
```

Host browser `localhost:8000/health` call பண்ணும். Container app `0.0.0.0:8000`-ல் listen செய்ய வேண்டும்; `127.0.0.1` container-க்குள் மட்டும் accessible ஆகலாம்.

## Real-time analogy: repeatable lab kit

<Scenario title="ஒவ்வொருவருக்கும் same working kit">

Training lab-க்கு code மட்டும் கொடுத்தால் learners different versions install செய்து different errors பெறலாம். Sealed kit-ல் runtime, dependencies மற்றும் instructions together இருந்தால் same exercise consistently run ஆகும். Docker image அந்த repeatable kit மாதிரி.

## Evidence-உடன் troubleshoot பண்ணுங்க

`docker ps -a`, `docker logs`, image tag, port mapping மற்றும் application bind address check பண்ணுங்க. Random rebuild செய்யாமல் failed layer அல்லது runtime error identify பண்ணுங்க.

## Production improvement

Pinned dependencies, non-root user, smaller base image, health check, vulnerability scan மற்றும் runtime secrets use பண்ணுங்க. Build tools final image-ல் தேவையில்லையென்றால் multi-stage build consider பண்ணலாம்.

## Common mistakes

<Mistakes>

- App local-ல் run ஆகிறதா verify செய்யாமல் Docker debug பண்ணுவது.
- `.venv` மற்றும் secrets image-க்கு copy பண்ணுவது.
- Application `localhost` மட்டும் bind பண்ணுவது.
- Reproducible version tag இல்லாமல் image build பண்ணுவது.
- Container shell-ல் manual package install செய்து fix preserve ஆனது என்று நினைப்பது.

</Mistakes>

## Interview-ல் எப்படி explain பண்ணுவது?

<ThemeCard title="docker build மற்றும் docker run-ல் என்ன நடக்கும்?" badge="CAREER">

`docker build` Dockerfile instructions மற்றும் build context use செய்து immutable image layers உருவாக்கும். `docker run` அந்த image-லிருந்து writable runtime layer, network மற்றும் process கொண்ட container instance create பண்ணும்.

</ThemeCard>
