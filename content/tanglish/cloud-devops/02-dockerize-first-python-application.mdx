## Docker open பண்ணும் முன் இந்த 4 questions

Dockerize செய்வதற்கு முன்: app local-ல் work ஆகுதா? Start command என்ன? எந்த port-ல் listen ஆகுது? Required packages எங்கே list பண்ணியிருக்கோம்? இதை first confirm பண்ணுங்க. Already broken-ஆ இருக்கும் app-ஐ Docker magic-ஆ fix பண்ணாது.

## Dockerfile-na app packing instruction

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY app.py .
EXPOSE 8000
CMD ["python", "app.py"]
```

Base image runtime கொடுக்கும். `WORKDIR` container working folder define செய்யும். Dependency file-ஐ முதலில் copy செய்தால் code-only changes-க்கு build cache reuse ஆகும். Exec-form `CMD` signal handling-க்கு better.

### ஒவ்வொரு line-மும் என்ன சொல்லுது?

`FROM` base runtime-ஐ select பண்ணும். `WORKDIR` next commands எந்த folder-ல் run ஆகணும் என்று set பண்ணும். Dependency file-ஐ source code-க்கு முன்னாடி copy செய்தால், code மட்டும் change ஆகும்போது installation layer cache-லிருந்து reuse ஆகும். `CMD`, container start ஆகும்போது run ஆக வேண்டிய foreground process-ஐ define பண்ணும்.

## தேவையில்லாத files image-க்குள் போகக்கூடாது

`.git`, `.venv`, cache, local logs, secrets மற்றும் unnecessary files build context-க்கு போகாமல் exclude செய்யுங்கள். Smaller context build speed மற்றும் accidental data exposure reduce செய்யும்.

## மூன்று commands: build → run → check

```bash
docker build -t delivery-status:1.0 .
docker run --rm -p 8000:8000 delivery-status:1.0
```

Host browser `localhost:8000/health` call செய்யும். Container app `0.0.0.0:8000`-ல் listen செய்ய வேண்டும்; `127.0.0.1` container-க்குள் மட்டும் accessible ஆகலாம்.

## Work ஆகலையா? இந்த order-ல் check பண்ணுங்க

`docker ps -a`, `docker logs`, image tag, port mapping மற்றும் application bind address check செய்யுங்கள். Random rebuild செய்யாமல் failed layer அல்லது runtime error identify செய்யுங்கள்.

## Local demo-விலிருந்து production-க்கு

Pinned dependencies, non-root user, smaller base image, health check, vulnerability scan மற்றும் runtime secrets use செய்யுங்கள். Build tools final image-ல் தேவையில்லையென்றால் multi-stage build consider செய்யலாம்.

## Common mistakes

<Mistakes>

- App local-ல் run ஆகிறதா verify செய்யாமல் Docker debug செய்வது.
- `.venv` மற்றும் secrets image-க்கு copy செய்வது.
- Application `localhost` மட்டும் bind செய்வது.
- Reproducible version tag இல்லாமல் image build செய்வது.
- Container shell-ல் manual package install செய்து fix preserve ஆனது என்று நினைப்பது.

</Mistakes>

## Interview answer—build vs run

<ThemeCard title="docker build மற்றும் docker run-ல் என்ன நடக்கும்?" badge="CAREER">

`docker build`, Dockerfile instructions மற்றும் build context use செய்து immutable image layers create பண்ணும். `docker run`, அந்த image-லிருந்து writable runtime layer, network மற்றும் process கொண்ட container instance create பண்ணும்.

</ThemeCard>
