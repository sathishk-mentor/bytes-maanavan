## Three problems—three Docker features

- User request container-ஐ எப்படி reach செய்யும்? **Port**.
- Container replace ஆனாலும் data எப்படி remain ஆகும்? **Volume**.
- Environment-specific setting எப்படி change ஆகும்? **Environment variable**.

## Problem 1: browser-லிருந்து app open ஆகணும்

Port-ஐ door number மாதிரி நினைச்சுக்கோங்க. Browser laptop-ன் `8080` door-க்கு வரும். Docker அந்த request-ஐ container-ன் `8000` door-க்கு அனுப்பும்.

```bash
docker run -p 8080:8000 delivery-status:1.0
```

இதைக் `laptop door : container door` என்று read பண்ணுங்க. Browser-ல் `localhost:8080` open பண்ணினால் container app response கொடுக்கும்.

`EXPOSE 8000` Dockerfile-ல் information மட்டும். Browser-க்கு door open பண்ணுவது `-p` option.

## Problem 2: container delete ஆனாலும் data இருக்கணும்

Container-ஐ whiteboard மாதிரி நினைச்சுக்கோங்க: erase செய்தால் அதில் எழுதியது போகலாம். Volume separate notebook மாதிரி. Container replace ஆனாலும் notebook data அப்படியே இருக்கும்.

```bash
docker volume create delivery-data
docker run -v delivery-data:/app/data delivery-status:1.0
```

Left side `delivery-data` என்பது Docker manage செய்யும் volume name. Right side `/app/data` என்பது container-க்குள் app data எழுதும் folder.

## Problem 3: same image; different settings

Same food app-ஐ development-ல் `LOG_LEVEL=debug`, production-ல் `LOG_LEVEL=info` என்று run பண்ண வேண்டியிருக்கலாம். Setting change செய்ய image rebuild தேவையில்லை.

```bash
docker run -e LOG_LEVEL=debug delivery-status:1.0
```

Environment variable என்பது start time setting. Password அல்லது API key-ஐ image-க்குள் எழுதக்கூடாது; production-ல் platform secret system use பண்ண வேண்டும்.

## மூன்றையும் ஒரே delivery app-ல் connect பண்ணலாம்

<Scenario title="One application, three runtime needs">

Customer `8080` door வழியாக app-ஐ open பண்ணுகிறார். Delivery history volume-ல் save ஆகுது. `LOG_LEVEL` start time-ல் environment variable மூலம் வருது. Container-ஐ replace செய்தாலும் history volume-ல் safe-ஆ இருக்கும்.

</Scenario>

### Volume-ஆ, bind mount-ஆ?

| Need | Use |
|---|---|
| Container replace ஆனாலும் app data இருக்கணும் | Named volume |
| Laptop source file change உடனே container-க்கு தெரியணும் | Bind mount |
| Temporary file மட்டும் | Container filesystem |

## Customer request எப்படி travel ஆகுது?

**Browser → laptop port → container port → app → response**. Page open ஆகலனா இந்த order-ல் check பண்ணுங்க. Data missing என்றால் volume mount check பண்ணுங்க. Wrong setting என்றால் environment variable name check பண்ணுங்க.

## Issue வந்தால் first என்ன பார்க்கணும்?

Running container port mapping, mounted volumes, environment variable names, logs மற்றும் network inspect செய்யுங்கள். Secret values output-ல் expose பண்ணாதீங்க.

## Common mistakes

<Mistakes>

- `EXPOSE` மட்டும் host port publish செய்யும் என்று நினைப்பது.
- Important data container writable layer-ல் store செய்வது.
- Secret-ஐ image, compose file அல்லது Git-ல் commit செய்வது.
- Environment variable missing ஆனாலும் unsafe default use செய்வது.
- Port conflict-க்கு application code change செய்வது.

</Mistakes>

## Interview answer—three different jobs

<ThemeCard title="Ports, volumes மற்றும் environment variables difference?" badge="CAREER">

Port network traffic-ஐ container service-க்கு map செய்யும். Volume container lifecycle-லிருந்து persistent data-ஐ separate செய்யும். Environment variable image rebuild இல்லாமல் runtime configuration வழங்கும். மூன்றும் different runtime concerns solve செய்யும்.

</ThemeCard>
