## Three questions, three Docker features

- User request container-ஐ எப்படி reach பண்ணும்? **Port**.
- Container replace ஆனாலும் data எப்படி remain ஆகும்? **Volume**.
- Environment-specific setting எப்படி change ஆகும்? **Environment variable**.

## Ports: container address மற்றும் host address

`-p 8080:8000` என்றால் host port `8080`-க்கு வரும் traffic container port `8000`-க்கு forward ஆகும். App container-க்குள் `0.0.0.0:8000`-ல் listen செய்ய வேண்டும்.

Port publish செய்வது authentication இல்லை. Sensitive service-ஐ unnecessary public interface-ல் expose பண்ணாதீங்க.

## Volumes: container replace செய்யலாம்; data remain ஆக வேண்டும்

Container filesystem ephemeral. Database data, uploaded files அல்லது durable state-க்கு named volume அல்லது managed external storage use பண்ணுங்க. Application code-ஐ production volume-ல் hide செய்வது avoid பண்ணுங்க.

## Environment variables: runtime configuration

Database URL, log level, feature flag போன்ற settings environment மூலம் inject பண்ணலாம். Secret values image-ல் bake பண்ணாமல் secret manager மூலம் runtime-ல் வழங்க வேண்டும். Missing required setting-க்கு app startup-லேயே clear error கொடுக்க வேண்டும்.

## Real-time scenario: delivery-status service

<Scenario title="One application, three runtime needs">

Customer `8080` port மூலம் status API-ஐ reach பண்ணுகிறார். Delivery events volume/database-ல் persist ஆகிறது. `LOG_LEVEL` மற்றும் provider endpoint environment-க்கு ஏற்றபடி configure ஆகிறது. Container update ஆனாலும் history safe-ஆக இருக்கும்.

</Scenario>

## One request-ஐ trace பண்ணுங்க

Browser → host port → container port → application route → database volume/service → response. எந்த boundary-ல் failure என்று logs மற்றும் inspection மூலம் கண்டுபிடிக்க வேண்டும்.

## Change செய்வதற்கு முன் inspect பண்ணுங்க

Running container port mapping, mounted volumes, environment variable names, logs மற்றும் network inspect பண்ணுங்க. Secret values output-ல் expose பண்ணாதீங்க.

## Common mistakes

<Mistakes>

- `EXPOSE` மட்டும் host port publish பண்ணும் என்று நினைப்பது.
- Important data container writable layer-ல் store பண்ணுவது.
- Secret-ஐ image, compose file அல்லது Git-ல் commit பண்ணுவது.
- Environment variable missing ஆனாலும் unsafe default use பண்ணுவது.
- Port conflict-க்கு application code change பண்ணுவது.

</Mistakes>

## Interview-ல் எப்படி explain பண்ணுவது?

<ThemeCard title="Ports, volumes மற்றும் environment variables difference?" badge="CAREER">

Port network traffic-ஐ container service-க்கு map பண்ணும். Volume container lifecycle-லிருந்து persistent data-ஐ separate பண்ணும். Environment variable image rebuild இல்லாமல் runtime configuration வழங்கும். மூன்றும் different runtime concerns solve பண்ணும்.

</ThemeCard>

## நினைவில் வைக்க வேண்டிய key points

<Takeaways>

- Port connectivity; volume durability; environment configuration.
- Container replaceable-ஆக design பண்ண வேண்டும்.
- Secrets runtime secret system-லிருந்து வர வேண்டும்.
- Exposed port security control இல்லை.
- Request path trace செய்தால் debugging clearer ஆகும்.

</Takeaways>
