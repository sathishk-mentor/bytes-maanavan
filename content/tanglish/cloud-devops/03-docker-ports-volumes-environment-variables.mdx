## Three questions, three Docker features

- User request container-ஐ எப்படி reach செய்யும்? **Port**.
- Container replace ஆனாலும் data எப்படி remain ஆகும்? **Volume**.
- Environment-specific setting எப்படி change ஆகும்? **Environment variable**.

## Ports: container address மற்றும் host address

`-p 8080:8000` என்றால் host port `8080`-க்கு வரும் traffic container port `8000`-க்கு forward ஆகும். App container-க்குள் `0.0.0.0:8000`-ல் listen செய்ய வேண்டும்.

Port publish செய்வது authentication இல்லை. Sensitive service-ஐ unnecessary public interface-ல் expose பண்ணாதீங்க.

## Volumes: container change ஆனாலும் data இருக்கணும்

Container filesystem ephemeral. Database data, uploaded files அல்லது durable state-க்கு named volume அல்லது managed external storage use செய்யுங்கள். Application code-ஐ production volume-ல் hide செய்வது avoid செய்யுங்கள்.

## Environment variables: runtime configuration

Database URL, log level, feature flag மாதிரியான settings-ஐ environment மூலம் inject பண்ணலாம். Secret values-ஐ image-ல் bake பண்ணாமல் secret manager மூலம் runtime-ல் கொடுக்கணும். Required setting missing என்றால் app startup-லேயே clear error காட்டணும்.

## Real-time scenario: delivery-status service

<Scenario title="One application, three runtime needs">

Customer `8080` port மூலம் status API-ஐ access பண்ணுகிறார். Delivery events volume அல்லது database-ல் persist ஆகும். `LOG_LEVEL` மற்றும் provider endpoint ஒவ்வொரு environment-க்கும் match ஆக configure செய்யப்படும். Container update ஆனாலும் history safe-ஆ இருக்கும்.

</Scenario>

### Named volume அல்லது bind mount?

Named volume-ஐ Docker manage செய்யும்; database data போன்ற runtime state-க்கு இது நல்ல default. Bind mount host folder-ஐ container-க்கு நேரடியாக இணைக்கும்; local source-code development-க்கு பயனுள்ளதாக இருக்கும். இரண்டையும் ஒரே purpose-க்கு பயன்படுத்த வேண்டிய அவசியமில்லை.

## ஒரு request-ன் பயணத்தை trace செய்யுங்கள்

Browser → host port → container port → application route → database volume/service → response. எந்த boundary-ல் failure என்று logs மற்றும் inspection மூலம் கண்டுபிடிக்க வேண்டும்.

## Change செய்வதற்கு முன்னாடி inspect பண்ணுங்க

Running container port mapping, mounted volumes, environment variable names, logs மற்றும் network inspect செய்யுங்கள். Secret values output-ல் expose பண்ணாதீங்க.

## Common mistakes

<Mistakes>

- `EXPOSE` மட்டும் host port publish செய்யும் என்று நினைப்பது.
- Important data container writable layer-ல் store செய்வது.
- Secret-ஐ image, compose file அல்லது Git-ல் commit செய்வது.
- Environment variable missing ஆனாலும் unsafe default use செய்வது.
- Port conflict-க்கு application code change செய்வது.

</Mistakes>

## Interview-ல் எப்படி explain செய்வது?

<ThemeCard title="Ports, volumes மற்றும் environment variables difference?" badge="CAREER">

Port network traffic-ஐ container service-க்கு map செய்யும். Volume container lifecycle-லிருந்து persistent data-ஐ separate செய்யும். Environment variable image rebuild இல்லாமல் runtime configuration வழங்கும். மூன்றும் different runtime concerns solve செய்யும்.

</ThemeCard>

## நினைவில் வைக்க வேண்டிய key points

<Takeaways>

- Port connectivity; volume durability; environment configuration.
- Container replaceable-ஆக design பண்ண வேண்டும்.
- Secrets runtime secret system-லிருந்து வர வேண்டும்.
- Exposed port security control இல்லை.
- Request path trace செய்தால் debugging clearer ஆகும்.

</Takeaways>
