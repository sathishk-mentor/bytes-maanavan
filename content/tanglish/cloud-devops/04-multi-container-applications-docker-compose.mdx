## Single container போதாத real app

Food-delivery app-க்கு frontend மட்டும் போதாது. Order API வேண்டும், database வேண்டும், notification service வேண்டும். ஒவ்வொன்றுக்கும் separate `docker run` command maintain பண்ணினால் port அல்லது environment setting miss ஆகும். Another developer same setup ready பண்ணுவதும் difficult.

Docker Compose எல்லா services, network, volume, port மற்றும் health check-ஐ ஒரே readable file-ல் declare செய்ய உதவும்.

## நம்ம delivery app team

<HandbookLearningVisual variant="dockerCompose" />

Browser `localhost:3000` மூலம் frontend-ஐ access பண்ணும். Frontend, Compose network-ல் `http://order-api:8000` URL use செய்து API-ஐ call பண்ணும். API, `postgres:5432` என்ற service name மூலம் database-ஐ access பண்ணும்.

## `compose.yaml`-ஐ story மாதிரி read பண்ணலாம்

```yaml
services:
  order-api:
    build: ./api
    ports:
      - "8000:8000"
    environment:
      DATABASE_URL: postgresql://app:app@postgres:5432/orders
    depends_on:
      postgres:
        condition: service_healthy

  postgres:
    image: postgres:17
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: app
      POSTGRES_DB: orders
    volumes:
      - order-data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U app"]
      interval: 10s
      timeout: 5s
      retries: 5

volumes:
  order-data:
```

இது learning configuration மட்டும். Real production password-ஐ file-ல் hardcode பண்ணக்கூடாது.

## Beginners அதிகம் miss பண்ணும் `localhost` rule

Container-க்குள் `localhost` என்றால் அந்த same container. அது மற்ற service இல்லை. அதனால் API database-ஐ `localhost:5432` மூலம் அல்ல, `postgres:5432` மூலம் access பண்ண வேண்டும்.

## Start ஆனது வேறு; ready ஆனது வேறு

Process start ஆனது service ready என்று அர்த்தம் இல்லை. Health check readiness-க்கு better signal கொடுக்கும். ஆனாலும் service later fail ஆகலாம்; application timeout, bounded retry மற்றும் clear error handle பண்ண வேண்டும்.

## Daily use-க்கு தேவையான commands

```bash
docker compose up --build
docker compose ps
docker compose logs -f order-api
docker compose exec order-api sh
docker compose down
```

`docker compose down -v` named volumes-ஐயும் delete பண்ணும். Database data-ஐ delete செய்ய வேண்டும் என்று clear-ஆ decide செய்தால் மட்டும் இதை use பண்ணுங்க.

## Easy analogy: restaurant team

<Scenario title="One order, multiple specialised stations">

Restaurant-ல் counter, kitchen, pantry மற்றும் billing எல்லாம் separate stations. Customer experience ஒன்றுதான்; but ஒவ்வொரு station-க்கும் clear name மற்றும் responsibility இருக்கும். Compose அந்த operating plan மாதிரி—எந்த services இருக்கு, எப்படி connect ஆகுது, எது first ready ஆகணும் என்பதை define பண்ணும்.

</Scenario>

## எல்லாத்தையும் restart பண்ணாதீங்க—இந்த order-ல் debug பண்ணுங்க

1. `docker compose config` மூலம் resolved configuration-ஐப் பாருங்கள்.
2. `docker compose ps` மூலம் service மற்றும் health state-ஐப் பாருங்கள்.
3. Failed request-ஐ பெற்ற service-ன் logs-ஐ முதலில் பாருங்கள்.
4. Container-to-container URL-ல் wrong-ஆ `localhost` use பண்ணியிருக்கீங்களா check பண்ணுங்க.
5. Environment variables மற்றும் database migration-ஐ verify செய்யுங்கள்.

## Common mistakes

<Mistakes>

- Another container-ஐ `localhost` மூலம் call செய்வது.
- எல்லா internal ports-ஐ host-க்கு publish செய்வது.
- Startup order-ஐ readiness guarantee என்று நினைப்பது.
- Production secrets-ஐ `compose.yaml`-ல் எழுதுவது.
- `docker compose down -v` effect புரியாமல் database volume delete செய்வது.

</Mistakes>

## Interview answer—Compose networking

<ThemeCard title="Docker Compose-ல் services எப்படி communicate செய்கின்றன?" badge="CAREER">

Compose application-க்கு default network create பண்ணும். அந்த network-ல் service names, DNS names மாதிரி work ஆகும். Internal traffic container port-ஐ use பண்ணும்; host வழியாக access தேவைப்படும் service-க்கு மட்டும் port publish பண்ணப்படும். Container start ஆனாலே ready என்று assume செய்யாமல் health checks மற்றும் application-level retry use பண்ணுவேன்.

</ThemeCard>
