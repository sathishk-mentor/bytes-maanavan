## Image-க்குள் என்ன இருக்கணும்? Outside என்ன இருக்கணும்?

ஒரு AI support app “என் order எங்கே?” என்ற question receive பண்ணும். App order details check செய்து LLM-க்கு required context அனுப்பி answer return பண்ணும். இங்கு two boxes நினைவில் வைங்க:

| Image-க்குள் | Image-க்கு outside |
|---|---|
| App code | LLM API key |
| Python libraries | Production database password |
| Start command | Environment-specific URL |

Code team-க்கு share செய்யலாம். Secret share செய்யக்கூடாது. அதனால் இரண்டையும் same image-க்குள் mix பண்ணக்கூடாது.

```python
import os
from fastapi import FastAPI, HTTPException

app = FastAPI()

@app.get("/health")
def health():
    return {"status": "healthy"}

@app.post("/support")
def support(question: str):
    if not os.getenv("LLM_API_KEY"):
        raise HTTPException(500, "LLM provider is not configured")
    return {"answer": f"Demo response for: {question}"}
```

## Safer production image build பண்ணலாம்

```dockerfile
FROM python:3.12-slim
WORKDIR /app
RUN addgroup --system app && adduser --system --ingroup app app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY --chown=app:app app.py .
USER app
EXPOSE 8000
CMD ["uvicorn", "app:app", "--host", "0.0.0.0", "--port", "8000"]
```

New part `USER app`. இதனால் application admin/root permission இல்லாமல் run ஆகும். Door key எல்லாம் ஒரே person-க்கு கொடுக்காதது மாதிரி, app-க்கு தேவையான permission மட்டும் கொடுப்பது safer default.

## API key image-க்குள் போகவே கூடாது

`COPY .env .` அல்லது Dockerfile-ல் API key எழுதினால் image share ஆகும் இடமெல்லாம் secret போகும் risk இருக்கு. Local practice-ல் runtime environment variable use பண்ணலாம். Production-ல் hosting platform secret settings use பண்ணணும்.

## User question வந்ததும் என்ன நடக்குது?

<HandbookLearningVisual variant="dockerAi" />

User question app URL-க்கு வரும் → API container question validate பண்ணும் → order data read பண்ணும் → LLM provider-ஐ call பண்ணும் → answer user-க்கு return ஆகும். எந்த step slow அல்லது fail என்று logs help பண்ணும்.

## Peak-time scenario: “என் order எங்கே?”

<Scenario title="Demo start ஆகுவது மட்டும் success இல்லை">

ஒரே நேரத்தில் நிறைய customers question கேட்கலாம். LLM late-ஆ answer பண்ணலாம் அல்லது provider error கொடுக்கலாம். App unlimited-ஆ retry பண்ணினால் cost அதிகமாகும். அதனால் team question length limit, timeout, retry limit மற்றும் request cost limit set பண்ணும். Container green light காட்டுது மட்டும் success இல்லை; useful answer correct time-ல் வரணும்.

</Scenario>

## App alive-ஆ? Traffic handle பண்ண ready-ஆ?

| Check | அது சொல்லும் விஷயம் |
|---|---|
| Liveness | App process run ஆகுதா? |
| Readiness | New user request accept பண்ண ready-ஆ? |
| Evaluation | Answer expected quality meet ஆகிறதா? |
| Cost metric | Request ஒன்றுக்கு tokens/cost எவ்வளவு? |

Paid LLM call-ஐ frequent liveness probe-ஆக use பண்ணாதீங்க.

## Deploy button click பண்ணும் முன்

1. Image-க்கு clear version tag கொடுங்கள்: `support-app:1.0`.
2. API key image-க்குள் இல்லை என்று confirm பண்ணுங்கள்.
3. App non-root user-ஆ run ஆகுதா check பண்ணுங்கள்.
4. Health URL response கொடுக்குதா test பண்ணுங்கள்.
5. Timeout, retry limit மற்றும் cost limit set பண்ணுங்கள்.
6. First small user group-க்கு release பண்ணுங்கள்.
7. Problem வந்தால் previous version-க்கு return ஆக rollback ready வைத்திருங்கள்.

## Problem வந்தால் எங்கே start பண்ணுவது?

| Symptom | First check பண்ண வேண்டிய evidence | Possible reason |
|---|---|---|
| Container மீண்டும் மீண்டும் restart ஆகிறது | Platform events மற்றும் startup logs | Missing variable, wrong command அல்லது memory limit |
| Request timeout ஆகிறது | Dependency latency trace | Provider delay, network அல்லது timeout mismatch |
| Provider `401` return செய்கிறது | Safe error category மற்றும் secret version | Invalid, expired அல்லது unauthorized key |
| Local-ல் works; cloud-ல் fail | Bind address, port மற்றும் platform contract | Wrong port அல்லது `localhost` binding |
| Cost திடீரென உயர்கிறது | Request count, tokens மற்றும் retry metrics | Unbounded input, retry storm அல்லது abuse |
| Release-க்குப் பிறகு answer quality குறைகிறது | Evaluation results by version | Prompt, model, retrieval அல்லது data change |

## Common mistakes

<Mistakes>

- Provider key-ஐ Dockerfile அல்லது image context-ல் copy செய்வது.
- Every provider error-ஐ retry செய்து cost storm create பண்ணுவது.
- `latest` tag மட்டும் deploy செய்து rollback version தெரியாமல் போவது.
- Full private prompts-ஐ logs-ல் store செய்வது.
- Infrastructure uptime மட்டும் பார்த்து answer quality ignore செய்வது.

</Mistakes>
