## 60 seconds-ல் FDE role

FDE customer environment-க்கு அருகில் work செய்து real workflow-ஐ understand பண்ணி, product-ஐ adapt செய்து, production-ல் deploy செய்து measurable outcome prove பண்ணும் engineer. Requirement receive செய்து code deliver பண்ணுவது மட்டும் role இல்லை; problem discovery முதல் adoption வரை ownership இருக்கும்.

## FDE outcome loop

Observe real work → frame problem → design thin slice → deploy → measure → improve → reusable product learning capture.

ஒரு step-ல் கிடைக்கும் evidence அடுத்த step-ஐ change பண்ணலாம். அதனால் FDE fixed implementation plan-ஐ blindly follow பண்ண மாட்டார்.

## Real-time analogy: hospital bedside engineer

<Scenario title="Report மட்டும் அல்ல; actual workflow பார்க்க வேண்டும்">

Hospital management “patient delay reduce பண்ணுங்க” என்று கேட்கலாம். FDE registration, token, nurse handoff, doctor queue மற்றும் exception cases-ஐ நேரில் observe பண்ணுவார். Dashboard build செய்வதற்கு முன் delay எங்கே உருவாகிறது என்பதை evidence மூலம் கண்டுபிடிப்பார்.

</Scenario>

## FDE மற்றும் nearby roles

- **Software engineer:** Product capability build மற்றும் maintain பண்ணுவார்.
- **Solutions architect:** Architecture மற்றும் integration design guide பண்ணுவார்.
- **Consultant:** Problem analyse செய்து recommendation கொடுப்பார்.
- **FDE:** Customer reality-ல் solution adapt, deploy மற்றும் outcome prove பண்ணுவார்.

Company-க்கு company title மாறலாம்; field-facing engineering ownership தான் முக்கிய behaviour.

## Forward deployment எப்போது useful?

Workflow complex, data/environment customer-specific, product-market learning important, integration uncertainty அதிகம் அல்லது adoption code delivery-ஐ விட difficult என்றால் FDE model useful. Standard self-service product-க்கு every customer-க்கும் deep custom engineering தேவையில்லை.

## Common mistakes

<Mistakes>

- Customer கேட்ட feature-ஐ root problem என்று assume பண்ணுவது.
- Demo success-ஐ production outcome என்று report பண்ணுவது.
- Custom code அதிகமாக build செய்து reusable product path இல்லாமல் விடுவது.
- User adoption மற்றும் operational ownership ignore பண்ணுவது.
- Success metric define செய்யாமல் deployment start பண்ணுவது.

</Mistakes>

## நினைவில் வைக்க வேண்டிய key points

<Takeaways>

- FDE customer reality மற்றும் product engineering இடையே work பண்ணுகிறார்.
- Output அல்ல; measurable outcome முக்கியம்.
- Discovery, deployment, adoption மற்றும் feedback ஒரே loop.
- Custom work reusable product direction-ஐ support செய்ய வேண்டும்.
- Production evidence assumptions-ஐ replace பண்ணும்.

</Takeaways>
