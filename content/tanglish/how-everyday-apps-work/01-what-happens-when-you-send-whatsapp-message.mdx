## S4 — Architecture and Flow

**Online irukkura yaaravadhukku message anupumbodhu enna nadakkuthu-nnu oru simplified flow:**

```text
You tap Send
  → Message leaves your phone, reaches a WhatsApp server
  → Server figures out the recipient is currently connected
  → Server forwards the message to the recipient's device
  → Recipient's phone confirms it arrived
  → You see the tick status update
```

**Recipient offline irundha, flow branch aaguthu:**

```text
You tap Send
  → Message leaves your phone, reaches a WhatsApp server
  → Server checks: is the recipient currently connected? No.
  → Message is held ("queued") on the server, waiting
  → Recipient's phone reconnects later
  → Server delivers the held message
  → Recipient's phone confirms it arrived
  → You see the tick status update, now that delivery happened
```

Idhu "receiving side ready-a irukkura varaikkum edhavadhu vachu irukkuradhu" pattern, usually oru **queue**-nu solvom — sender-um receiver-um adhe moment-la active-a irupanga-nu guarantee illama irukkura edam ellame romba common-a irukkura oru building block.

**Tick marks commonly enna represent pannuthu-nu irukkalam:**

- **Ondru grey tick:** unga message WhatsApp server-ai adainjirukku, aana recipient-oda device-ai innum adaiyala — usually avanga offline-a irundha.
- **Rendu grey ticks:** message recipient-oda device-ai adainjirukku (delivered), avanga chat-ai open panna-alum.
- **Rendu blue ticks:** recipient chat-ai open pannirukaanga, message avanga screen-la display aayiduchu — idhu seen-nu kaamikkuthu, careful-a padichu understand pannirukaanga-nu illai.

## S7 — Failure Cases and Common Mistakes

1. **Ondru grey tick, always "avanga ennai ignore pannuraanga" illa "block pannitanga"-nu artham-nu nenaikkuradhu** — S4-la irukkura madhiri, usually idhu message avanga device-ai innum adaiyala-nu artham; blocking-ai private-a vaikka, WhatsApp offline-um blocked-um identical-a kaamikka design pannuthu-nu report aaguthu.
2. **Messages ondru phone-la irundhu vera phone-ku direct-a poguthu-nu nenaikkuradhu** — indha illustrative model-la, messages idaiyila irukkura oru server vazhi route aaguthu ("store-and-forward" pattern), phone-to-phone direct-a anuppaadhu, message content end-to-end encrypted irundhaalum, server adha padikka mudiyaadhu.
3. **"Delivered"-um "read"-um onnu-nu treat pannuradhu** — double grey ticks and blue ticks, rendu vera questions-ku answer solluthu (adhu adainjuduchaa vs display aaguduchaa); idha conflate pannuradhu, andha veroru person actual-a enna therinjukanaanga-nu wrong conclusions-ku vazhi vaikkalam.
4. **Oru messaging app-oda actual internals ellame publicly documented-nu nenaikkuradhu** — indha byte start-la-ye sonna madhiri, idhu public write-ups and reasonable inference-la irundhu build pannina oru illustrative model, confirmed internal architecture illai.
