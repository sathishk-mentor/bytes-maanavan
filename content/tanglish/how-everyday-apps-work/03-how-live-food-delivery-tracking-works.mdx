## Map-la moving dot enga irundhu varudhu?

Meena lunch order pannuraanga. App-la rider icon street-la move aagudhu. Karthik kekkiraar: “Map-la dot every second move aagudhe. Rider phone every second exact coordinate send pannudhaa?”

**Answer:** Avasiyam illa. Rider phone periodic location update send pannalam. App, vandha points idaiyila animation use panni dot-ai smooth-a move panna mudiyum.

## Rendu data types-ai separate-a paarunga

**Order status:** Restaurant accepted, preparing, picked up, delivered. Idhu business event; reliable-a store pannanum.

**Rider location:** Latitude, longitude, update timestamp. Idhu frequent-a change aagum; old position quick-a stale aagum.

Order “picked up” nu irundhaalum map dot old-a irukkalam. Adhanaala “last updated 2 min ago” madhiri clue customer-ku helpful.

## Oru update-oda journey

1. Rider phone GPS-la approximate location edukkum.
2. Network available-a irundha location update service-ku send pannum.
3. Service order and rider connection-ai check pannum.
4. Customer app-ku latest relevant position send pannalam; polling-um use pannalam.
5. Map latest coordinate-ai kaatti, movement-ai smooth-a animate pannalam.

Exact Swiggy/Zomato infrastructure full-a public illa. Idhu real-time tracking-ku oru **illustrative design**, fixed vendor stack claim illa.

## Network drop aana enna kaattanum?

Rider underpass-ku pogumbodhu 90 seconds update varalai. Dot-ai road mela imagine panni “live” nu kaattina customer wrong conclusion edukka mudiyum.

**Meena:** “Rider inge dhaan irukkaar-nu map solludhaa?”  
**Karthik:** “Last known location inga. Fresh update varala-nu timestamp kaattanum.”

Reconnect aana latest useful coordinate kaattanum. Old coordinates ellathaiyum fast-a replay panna customer-ku confusing-a irukkum.

## Busy hour-la scale

Oru rider mattum illa; thousands of riders update send pannuvaanga. Ella customer-kum ella rider location thevai illa. Andha order-ku related rider updates mattum distribute pannina network load kuraiyum. Update frequency, battery, accuracy, privacy — ellathukkum trade-off irukku.

## Customer view vs system view

| Customer paakradhu | System check pannuradhu |
|---|---|
| “Picked up” | Order state update |
| Moving dot | Latest position + display animation |
| “Last updated” | GPS report timestamp |
| “Delivered” | Delivery completion event |

## Try pannunga

Rider phone 3 minutes offline. Customer app-la oru small sentence design pannunga. Example: **“Location update 3 minutes-a varala; order status unchanged.”** Fresh location vandha sentence update aaganum.

## Ninaivil vechukka

- Order status and GPS location vera data.
- Smooth animation exact live movement-ku proof illa.
- Old location-ai “live” nu sollama timestamp kaattunga.
- Customer-ku relevant updates mattum send pannunga.

## Common questions

**WebSocket compulsory-a?** Illai. Push channel or polling — app requirements-ku suitable-aana method choose pannalam.

**Dot exact location-a?** GPS accuracy, network delay, animation ellam affect pannum; last known estimate-nu paakradhu better.
