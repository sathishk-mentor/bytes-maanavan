## Core Explanation

Namba SQL Handbook-oda aggregation concept ninaikonga: rows-ai group pannі, ovvoru group-ku-um oru summary value (madhiri `AVG()` illa `SUM()`) compute pannuрадhу. MongoDB-oda **aggregation pipeline**, adhе job pannuтхू, aаnа clearly-named *stages*-oda oru sequence-a structured aагі иருккும், data adhula irundhu poгум் — oru assembly line madhiri, ovvoru station-um (`$match`, `$group`, `$sort`, and matта-um) next station-ku kодуккка munnaadi data-ai konjum konjum transform pannுтхு.

Indha "pipeline of stages" structure, oru deeply nested SQL query-vidа usually padikка easy-a иருккும், yaenna ovvoru stage-um oru chinna, understandable step, adhа neenga independently reason pannna (test pannna-um) mудியуum்.


## Architecture and Flow Diagram

**"Customer-ku average transaction amount, last 30 days" compute pannuradhu — oru AI feature:**

```javascript
db.transactions.aggregate([
  {
    $match: {
      timestamp: { $gte: new Date(Date.now() - 30 * 24 * 60 * 60 * 1000) }
    }
  },
  {
    $group: {
      _id: "$customer_id",
      avg_transaction_amount: { $avg: "$amount" },
      transaction_count: { $sum: 1 }
    }
  },
  {
    $sort: { avg_transaction_amount: -1 }
  }
])
```

Ovvoru stage-ai, adhу-oda SQL Handbook equivalent-oda compare pannungal்: `$match` unga `WHERE` clause, `$avg` and `$sum`-oda `$group` unga aggregate functions-oda `GROUP BY`, and `$sort` unga `ORDER BY` — adhе underlying logic, oru readable sequence of steps-a express aayiтхи.

**`$setWindowFields` use pannі oru window-function-style feature (customer-ku rolling behavior):**

```javascript
db.transactions.aggregate([
  {
    $setWindowFields: {
      partitionBy: "$customer_id",
      sortBy: { timestamp: 1 },
      output: {
        running_total: { $sum: "$amount", window: { documents: ["unbounded", "current"] } }
      }
    }
  }
])
```

Idhu namba SQL Handbook-oda `SUM() OVER (PARTITION BY ... ORDER BY ...)` pattern-ai almost directly mirror pannுтхु — MongoDB-oda `$setWindowFields` stage-thán் adhу-oda window function equivalent.

## Common Mistakes

1. **`$match` illa `$sort`-la use aагுра fields-la index illama aggregations run pannuradhu** — oru unindexed SQL `WHERE` clause madhiri-yе, idhу MongoDB-ai venumaadhathukku vidа romba jasti documents scan panna vali vaккலाam்.
2. **Incrementally stages test pannатіка, oru periya single pipeline build pannuradhu** — ovvoru stage-oda output next stage-ku poгுrадhal், ovvoru stage-ku apuram individually result-ai check pannі pipeline-ai debug pannuрадhу romба easy-a иருккும்.
3. **`$merge` data eludhutху-nu marandhu poradhu, mattum் return pannатхே** — most aggregation stages-vidа vेறу-a, `$merge`-ku oru real side effect иருккு (oru collection-la eludhuradhу); idhа production collection-la experimentally use pannінा, live data-ai overwrite panna vali vaккиридhu.
4. **Ovvoru single request-kkum adhе aggregation-ai recompute pannuradhu** — expensive features-ku (30-day rolling averages madhiri), S5-la иருккура madhiri precompute pannі store pannungal், ovvoru API call-kkum full aggregation run pannатीka.

## Comparison

| Concept | SQL Handbook | MongoDB Aggregation Pipeline |
|---|---|---|
| Filtering rows | `WHERE` | `$match` |
| Grouping + aggregate functions | `GROUP BY` + `AVG()`/`SUM()` | `$group` with `$avg`/`$sum` |
| Ordering results | `ORDER BY` | `$sort` |
| Window functions | `SUM() OVER (PARTITION BY ...)` | `$setWindowFields` |
| Writing results to a new table/collection | `INSERT INTO ... SELECT` | `$merge` |

## Key Takeaways

- MongoDB-oda **aggregation pipeline**, SQL-oda `GROUP BY`/aggregate functions madhiri adhе job pannутху, data poгура readable sequence of named stages-a structured aагі.
- `$match`, `$group`, and `$sort`, SQL-oda `WHERE`, `GROUP BY`, and `ORDER BY`-la almost directly map aагுтхு.
- `$setWindowFields`, window-function-style calculations (running totals, rolling averages) kодуккутху, SQL-oda `OVER (PARTITION BY ...)` equivalent.
- `$merge`, compute pannitха features-ai directly oru collection-la eludhutхू, AI models-ai precomputed features-ai separate export step illama consume panna vidutхू.
- MongoDB, in-database computation-ku actively optimize aагиkondu иருккு, common features compute panна external pipelines venum்-nu eliminate panna aim pannі.
