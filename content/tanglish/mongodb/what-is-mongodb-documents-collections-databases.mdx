## Core Explanation

Namba SQL Handbook-oda foundation ninaikonga: rows and columns, oru table-la ovvoru row-um exact adhе columns иருkkanum், most-um empty (`NULL`) иருндhalும் oru specific record-ku. Oru SQL table-ai, oru printed form fixed boxes-oda madhiri nenachуconga — ovvoru submission-um adhе boxes use pannுтхு, blank-a иருndhalум். Oru MongoDB collection, oru filing folder madhiri, adhуla иருккура ovvoru paper-um vेறு vेறу shape-a иருkka mудியуum் — oru receipt, oru letter, oru photo — ella-um adhе general topic-oda related-a иருндhaа podhум். AI conversations-ku, ondru exchange-la oru tool call иருkkалam், adhутхаваthу-la illama poгалाam், indha flexibility, romba awkward, mostly-empty columns-ai avoid pannuтху.

1. **"Flexible schema" meaning "design discipline venамா"-nu nenaikkuradhu** — collection-la иருккura documents, unga application-oda core fields-ku still broadly consistent shape follow pananum்; flexibility, genuine variation-ku, planning skip panна excuse illai.

## Comparison

| Aspect | SQL (Relational) | MongoDB (Document) |
|---|---|---|
| Structure | Fixed columns per table | Flexible fields per document |
| Varying data shapes | Nullable columns or extra tables | Natural — just add/omit fields |
| Adding a new field | Schema migration (`ALTER TABLE`) | No migration needed |
| Best fit | Highly structured, uniform records | Varied, evolving records (like AI conversation logs) |
