## Quick Start
Copilot Chat code explain pannalaam, bug investigate pannalaam, test suggest pannalaam. Answer quality-ai neenga share pannura context decide pannum.

## Meet the Scenario
Rahul “refund bug fix pannu” nu kekkarar. Copilot guess pannudhu. Failing test, `RefundService.java`, expected rule share pannumbodhu answer focused-a maarudhu.

## Core Concept
Strong request = **goal + relevant code + evidence + expected result**. Mudhal answer-ai final-nu accept pannaama evidence kekkanum.

## Context Ladder
| Weak request | Better context | Why better? |
|---|---|---|
| “Bug fix pannu” | Failing test + file + expected rule | Guessing kuraiyum |
| “Code explain pannu” | Function + caller + specific doubt | Relevant explanation kidaikkum |
| “Test write pannu” | Behaviour + edge cases + framework | Test purpose clear aagum |

## Chat Workflow
1. Problem-ai one sentence-la state pannunga.
2. Relevant file/function mattum attach pannunga.
3. Error message or failing test-ai evidence-a kudunga.
4. First root cause explanation kekkunga.
5. Small fix and verification steps separate-a request pannunga.

## Data Boundary
Customer data, production token, private key, internal credential-ai prompt-la paste panna koodadhu. Issue explain panna sanitised sample and minimum relevant context use pannunga.

## Better Prompt
```text
RefundService.java-la duplicate refund test fail aagudhu.
Stack trace-ai explain panni root cause sollunga.
Public API change pannaama smallest fix propose pannunga.
```

## Mini Practice
Oru vague request choose pannunga. Adhai `goal + relevant file + failure evidence + constraint + expected result` format-la rewrite pannunga. Lab-la rendu prompt output-ai compare pannunga.
