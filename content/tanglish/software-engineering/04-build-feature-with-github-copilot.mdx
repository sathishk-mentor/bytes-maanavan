## Thin vertical slice-லிருந்து start பண்ணுங்க

Complete feature-ஐ ஒரே prompt-ல் generate பண்ணுவது review risk அதிகரிக்கும். User-க்கு visible ஆன smallest end-to-end outcome choose பண்ணுங்க: UI action, API validation, business logic, storage மற்றும் test வழியாக ஒரு narrow path.

## Step 1: current system-ஐ establish பண்ணுங்க

Entry point, data flow, existing pattern, dependencies மற்றும் tests-ஐ Copilot explain செய்ய சொல்லுங்க. Confirmed evidence மற்றும் assumptions separate-ஆக இருக்க வேண்டும். Code change முன் human understanding தேவை.

## Step 2: plan-ஐ create செய்து challenge பண்ணுங்க

Files to change, contract impact, migration, security, edge cases மற்றும் tests கொண்ட plan கேளுங்க. “இந்த plan எங்கே fail ஆகலாம்?” என்று challenge பண்ணுங்க. Unnecessary scope remove பண்ணுங்க.

## Step 3: reviewable increments-ல் implement பண்ணுங்க

One logical change at a time: model/contract, service rule, API/UI integration, tests. ஒவ்வொரு increment பிறகும் diff inspect செய்து test run பண்ணுங்க. Generated command அல்லது dependency-ஐ blindly accept பண்ணாதீங்க.

## Step 4: syntax மட்டும் அல்ல; behaviour test பண்ணுங்க

Happy path, empty state, invalid input, permission failure, duplicate action மற்றும் dependency failure cover பண்ணுங்க. UI render ஆனது complete feature proof இல்லை.

## Step 5: final diff inspect பண்ணுங்க

Requirement unrelated changes, duplicated logic, missing validation, secret exposure, weak error handling, accessibility மற்றும் rollback impact check பண்ணுங்க.

## Easy analogy: one usable room first

<Scenario title="Complete building முன் one room">

Construction team முதலில் plan approve செய்து one usable room complete செய்து electrical, plumbing மற்றும் safety check பண்ணும். அதன் பிறகே pattern expand பண்ணும். Feature delivery-லும் small end-to-end slice uncertainty-ஐ early reveal பண்ணும்.

</Scenario>

## Real-time scenario: wishlist feature

User product-ஐ wishlist-ல் add பண்ண வேண்டும். First slice authenticated user, one add action, duplicate prevention, persistence, visible confirmation மற்றும் tests மட்டும் cover பண்ணும். Notifications, sharing மற்றும் recommendations later increments.

## Implementation prompt

<PromptBox label="Thin-slice implementation prompt">

Using the reviewed plan, implement only the smallest end-to-end slice. Follow existing repository patterns. Add validation and tests. Stop after this increment and summarise changed files, assumptions, commands run and remaining risks.

</PromptBox>

## Agent mode எப்போது wrong starting point?

Requirement unclear, repository unfamiliar, migration destructive, credentials unavailable அல்லது acceptance criteria missing என்றால் autonomous multi-file change start பண்ணாதீங்க. முதலில் exploration அல்லது planning mode use பண்ணுங்க.

## Common mistakes

<Mistakes>

- Complete feature-ஐ one large prompt-ல் generate பண்ணுவது.
- Plan review இல்லாமல் agent commands allow பண்ணுவது.
- Tests later add பண்ணலாம் என்று postpone பண்ணுவது.
- Unrelated formatting மற்றும் refactor-ஐ feature diff-ல் mix பண்ணுவது.
- Final output summary மட்டும் பார்த்து actual diff inspect பண்ணாமல் merge செய்வது.

</Mistakes>

## நினைவில் வைக்க வேண்டிய key points

<Takeaways>

- Thin slice early end-to-end evidence கொடுக்கும்.
- Plan-ஐ challenge செய்த பிறகே implementation start பண்ணுங்க.
- Small increments review மற்றும் recovery easy ஆக்கும்.
- Behaviour tests syntax success-ஐ விட meaningful.
- Final diff developer approval இல்லாமல் complete இல்லை.

</Takeaways>
