## Responsibility tool-க்கு transfer ஆகாது

Copilot code suggest அல்லது change prepare செய்தாலும் repository owner மற்றும் reviewing developer தான் result-க்கு accountable. “AI generated” என்பது weak design, vulnerability அல்லது broken requirement-க்கு excuse இல்லை.

## Five-gate review model

1. **Intent:** Change correct requirement-ஐ solve செய்கிறதா?
2. **Correctness:** Normal மற்றும் edge cases-ல் behaviour correct-ஆ?
3. **Security and privacy:** Input validation, permission, secrets மற்றும் data handling safe-ஆ?
4. **Maintainability:** Existing architecture, naming, dependencies மற்றும் tests-க்கு fit ஆகிறதா?
5. **Operations:** Logs, performance, rollout மற்றும் rollback ready-ஆ?

ஒரு gate fail ஆனால் change release ஆகக்கூடாது.

## Real-time scenario: risk-based code review

Text label change மற்றும் authentication rule change ஒரே review depth வேண்டியதில்லை. Data access, payment, identity, permission, deployment அல்லது destructive operation touch செய்யும் generated code-க்கு stronger tests, security review மற்றும் explicit approval தேவை.

## Release checklist

- Requirement மற்றும் acceptance criteria trace செய்யப்பட்டதா?
- Generated code line-by-line review ஆனதா?
- Unit, integration மற்றும் security tests pass ஆனதா?
- New dependency provenance மற்றும் license check ஆனதா?
- Secrets அல்லது private data output/log-ல் இல்லையா?
- Permission changes least privilege follow செய்கிறதா?
- Monitoring மற்றும் rollback plan ready-ஆ?
- Accountable human approver named-ஆ?

## Common mistakes

<Mistakes>

- Build pass ஆனதால் business behaviour correct என்று assume பண்ணுவது.
- Generated tests generated implementation-ஐ repeat பண்ணுவதை evidence என்று accept பண்ணுவது.
- Suggested package-ஐ provenance check இல்லாமல் install பண்ணுவது.
- Private code அல்லது production data-ஐ unapproved context-ல் share பண்ணுவது.
- High-risk change-ஐ same-day pressure காரணமாக review இல்லாமல் release பண்ணுவது.

</Mistakes>
