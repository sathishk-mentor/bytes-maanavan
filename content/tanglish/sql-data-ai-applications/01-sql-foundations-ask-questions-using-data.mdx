## Business question-லிருந்து start பண்ணுங்க

SQL என்பது relational database-கிட்ட precise question கேட்கும் language. Database-ல் tables இருக்கும்; table-க்கு named columns இருக்கும்; ஒவ்வொரு row-வும் store செய்யப்படும் ஒரு item அல்லது event-ஐ represent பண்ணும்.

| Table | ஒரு row எதை குறிக்கும்? | Example columns |
|---|---|---|
| `products` | ஒரு product | `product_id`, `name`, `category`, `price` |
| `customers` | ஒரு learner | `customer_id`, `name`, `country` |
| `orders` | ஒரு purchase | `order_id`, `customer_id`, `ordered_at` |

## தேவையான data மட்டும் read பண்ணுங்க

Question: “Highest price கொண்ட active headphones-ல் முதல் ஐந்தை காட்டுங்க.”

```sql
SELECT product_id, name, price
FROM products
WHERE category = 'Headphones' AND status = 'ACTIVE'
ORDER BY price DESC
LIMIT 5;
```

இதை இந்த logical order-ல் புரிந்துகொள்ளலாம்:

1. `FROM` எந்த table-லிருந்து data வேண்டும் என்று சொல்லும்.
2. `WHERE` matching rows மட்டும் retain பண்ணும்.
3. `SELECT` தேவையான columns மட்டும் return பண்ணும்.
4. `ORDER BY` result-ஐ arrange பண்ணும்.
5. `LIMIT` எத்தனை rows வேண்டும் என்று control பண்ணும்.

Application query-ல் `SELECT *` avoid பண்ணுங்க. Explicit columns use செய்தால் unnecessary data transfer குறையும்; future-ல் table-க்கு sensitive field add ஆனாலும் அது accidental-ஆக response-ல் வராது.

## Keys மூலம் rows-க்கு context கிடைக்கும்

**Primary key** ஒரு row-ஐ uniquely identify பண்ணும். **Foreign key** வேறு table-ல் இருக்கும் related row-ஐ point பண்ணும். Example: `orders.customer_id` ஒரு purchase-ஐ சரியான customer-உடன் connect பண்ணும். Byte 3-ல் இதை joins-ல் use பண்ணுவோம்.

<Scenario title="Library-ல் precise request கேட்பது">

“எல்லா products-ஐயும் காட்டுங்க” என்பது expensive மற்றும் unclear request. “Active headphones-ல் name, price மட்டும், highest price first, five results” என்று கேட்டால் category, filter, fields, order மற்றும் limit எல்லாம் clear. Good SQL query-யும் இதே மாதிரி explicit-ஆக இருக்கும்.

</Scenario>

## Beginners செய்யும் common mistakes

<Mistakes>

- இரண்டு columns மட்டும் தேவைப்படும்போது `SELECT *` use பண்ணுவது.
- `NULL`-ஐ `= NULL` மூலம் check பண்ணுவது; சரியான syntax `IS NULL`.
- Deterministic `ORDER BY` இல்லாமல் `LIMIT` use பண்ணுவது.
- Text மற்றும் numeric values-ன் type difference புரியாமல் compare பண்ணுவது.
- Read-only query learn செய்யும் நேரத்திலேயே data update பண்ணுவது.

</Mistakes>

## Interview-ல் எப்படி explain பண்ணுவது?

<ThemeCard title="WHERE மற்றும் ORDER BY வித்தியாசம் என்ன?" badge="CAREER">

`WHERE` எந்த rows result-க்கு qualify ஆகிறது என்பதை decide பண்ணும். `ORDER BY` qualify ஆன rows எந்த order-ல் display ஆக வேண்டும் என்பதை decide பண்ணும். Filtering result membership-ஐ change பண்ணும்; sorting presentation order-ஐ change பண்ணும்.

</ThemeCard>

## நினைவில் வைக்க வேண்டிய key points

<Takeaways>

- Precise business question-லிருந்து SQL query-ஐ start பண்ணுங்க.
- Table ஒரு consistent column structure-ல் related rows-ஐ store பண்ணும்.
- Explicit columns select செய்து, intentional filter மற்றும் bounded result use பண்ணுங்க.
- Keys tables இடையில் reliable relationship உருவாக்கும்.

</Takeaways>
