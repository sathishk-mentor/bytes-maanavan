## Rows எப்படி measures-ஆக மாறும்?

Aggregate functions பல rows-ஐ ஒரு meaningful summary-ஆக மாற்றும்:

| Function | Business meaning |
|---|---|
| `COUNT(*)` | Purchase count |
| `SUM(amount)` | Total revenue |
| `AVG(amount)` | Average order value |
| `MIN` / `MAX` | Smallest அல்லது largest value |

```sql
SELECT product_id, COUNT(*) AS orders, SUM(amount) AS revenue
FROM orders
WHERE ordered_at >= CURRENT_DATE - INTERVAL '3 months'
GROUP BY product_id
HAVING SUM(amount) > 10000
ORDER BY revenue DESC;
```

`WHERE` aggregation நடப்பதற்கு முன் individual rows-ஐ filter பண்ணும். `HAVING` aggregation முடிந்த பிறகு completed groups-ஐ filter பண்ணும்.

## Date boundary-ஐ explicit-ஆக define பண்ணுங்க

“Last three months” என்பது rolling 90 days ஆகவும் இருக்கலாம்; previous three complete calendar months ஆகவும் இருக்கலாம். இரண்டும் different answers கொடுக்கும். SQL எழுதுவதற்கு முன் business definition confirm பண்ணி, possible என்றால் `>= start` மற்றும் `< end` போன்ற half-open boundaries use பண்ணுங்க.

## Business categories-ஐ safely add பண்ணுவது

```sql
SELECT CASE
  WHEN amount >= 2000 THEN 'High value'
  WHEN amount >= 1000 THEN 'Mid value'
  ELSE 'Entry value'
END AS value_band, COUNT(*) AS purchases
FROM orders
GROUP BY value_band;
```

## Beginners செய்யும் common mistakes

<Mistakes>

- Aggregate ஆகாத column-ஐ `GROUP BY`-ல் சேர்க்காமல் select பண்ணுவது.
- `WHERE`-ல் இருக்க வேண்டிய filter-ஐ `HAVING`-ல் வைப்பது.
- Revenue calculate செய்யும்போது refund, currency அல்லது cancelled order-ஐ ignore பண்ணுவது.
- Business rule இல்லாமல் missing value-ஐ zero என்று treat பண்ணுவது.
- “Month” அல்லது “recent” என்பதற்கு ambiguous definition use பண்ணுவது.

</Mistakes>

## நினைவில் வைக்க வேண்டிய key points

<Takeaways>

- Aggregates transactions-ஐ measures-ஆக மாற்றும்.
- `GROUP BY` reporting grain-ஐ define பண்ணும்.
- `WHERE` rows-ஐ filter பண்ணும்; `HAVING` groups-ஐ filter பண்ணும்.
- Clear business definition இல்லாமல் metric complete ஆகாது.

</Takeaways>
