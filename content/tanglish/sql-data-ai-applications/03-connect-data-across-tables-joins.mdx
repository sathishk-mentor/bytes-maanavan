## Text முதலில் vector-ஆக மாறும்

Stored documents மற்றும் incoming query இரண்டிற்கும் **same embedding model** பயன்படுத்த வேண்டும். Model தான் vector dimension-ஐ தீர்மானிக்கும். `vector(1536)` column வேறு dimension vector-ஐ accept செய்யாது.

## pgvector setup

```sql
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE knowledge_chunks (
  chunk_id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  document_id bigint NOT NULL,
  content text NOT NULL,
  embedding vector(1536) NOT NULL
);
```

## Cosine distance மூலம் rank செய்வது

```sql
SELECT chunk_id, content,
       1 - (embedding <=> $1::vector) AS similarity
FROM knowledge_chunks
ORDER BY embedding <=> $1::vector
LIMIT 3;
```

`<=>` cosine-distance operator. Smaller distance என்றால் closer vectors. `$1` application வழங்கும் parameter; user text-ஐ SQL-உடன் concatenate செய்யக்கூடாது.

| chunk_id | content | similarity |
|---:|---|---:|
| 42 | Refunds are available within the return window… | 0.91 |
| 18 | Cancel an order before dispatch… | 0.72 |
| 67 | Product warranty coverage… | 0.48 |

## HNSW index எப்போது?

```sql
CREATE INDEX knowledge_chunks_embedding_hnsw
ON knowledge_chunks
USING hnsw (embedding vector_cosine_ops);
```

Exact search எல்லா vectors-உடனும் compare செய்யலாம். Larger collection-ல் HNSW search work-ஐ குறைக்கலாம். ஆனால் speed, memory மற்றும் recall-ஐ real data மூலம் measure செய்ய வேண்டும்.

இப்போது lab-ல் exact scan மற்றும் HNSW candidate search-ஐ compare செய்யுங்கள். `top-k` result count-ஐ மாற்றும்; index toggle candidate search path-ஐ மாற்றும்.

## பொதுவான mistakes

<Mistakes>

- Different embedding models-ன் vectors-ஐ compare செய்வது.
- `[0.12, ...]` போன்ற incomplete vector-ஐ runnable SQL என்று காட்டுவது.
- Query metric-க்கு match ஆகாத operator class index உருவாக்குவது.
- Similarity score-ஐ truth score என்று நினைப்பது.
- Recall test இல்லாமல் approximate search enable செய்வது.

</Mistakes>
