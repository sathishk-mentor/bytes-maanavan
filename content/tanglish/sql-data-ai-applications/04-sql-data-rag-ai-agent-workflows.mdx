## Fixed cutoff கொண்டு features உருவாக்குங்கள்

```sql
WITH parameters AS (
  SELECT DATE '2026-10-01' AS cutoff_date
)
SELECT c.customer_id,
       COUNT(t.transaction_id) FILTER (
         WHERE t.transaction_date >= p.cutoff_date - INTERVAL '30 days'
           AND t.transaction_date < p.cutoff_date
       ) AS orders_30d,
       COALESCE(SUM(t.amount) FILTER (
         WHERE t.transaction_date >= p.cutoff_date - INTERVAL '90 days'
           AND t.transaction_date < p.cutoff_date
       ), 0) AS spend_90d
FROM customers AS c
CROSS JOIN parameters AS p
LEFT JOIN transactions AS t
  ON t.customer_id = c.customer_id
 AND t.transaction_date < p.cutoff_date
GROUP BY c.customer_id;
```

Historical training set-ல் `CURRENT_DATE` பயன்படுத்தினால் result தினமும் மாறும். Fixed cutoff observation time-ஐ reproducible-ஆ வைத்திருக்கும்.

| customer_id | orders_30d | spend_90d |
|---|---:|---:|
| C101 | 7 | ₹18,420 |
| C102 | 2 | ₹3,100 |

## Point-in-time correctness ஏன் முக்கியம்?

Changing profile அல்லது price போன்ற data-க்கும் cutoff நேரத்தில் தெரிந்த version மட்டுமே பயன்படுத்த வேண்டும். Training மற்றும் production prediction ஒரே feature definition பயன்படுத்தாவிட்டால் **training-serving skew** வரும்.

<Scenario title="Practical scenario: churn prediction">

Churn model support tickets, payment failures, recent usage ஆகியவற்றைப் பயன்படுத்தலாம். ஒவ்வொரு input-மும் prediction moment-க்கு முன்பு இருந்த நிலையை மட்டும் காட்ட வேண்டும். Churn label future-ல் இருக்கும்; அது feature columns-ல் வரக்கூடாது.

</Scenario>

## பொதுவான mistakes

<Mistakes>

- Historical features-க்கு `CURRENT_DATE` பயன்படுத்துவது.
- Cutoff-க்கு பிறகான events-ஐ சேர்ப்பது.
- Business meaning இல்லாமல் `NULL`-ஐ zero-ஆக மாற்றுவது.
- Training மற்றும் serving-ல் வேறு feature logic பயன்படுத்துவது.
- Reproducible experiment இல்லாமல் accuracy claim செய்வது.

</Mistakes>
