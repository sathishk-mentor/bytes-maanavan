## Correct result மட்டும் போதாது

Production query bounded, efficient, authorised மற்றும் observable-ஆகவும் இருக்க வேண்டும். Correct result கொடுக்கும் query ஒவ்வொரு chat request-க்கும் millions of rows scan செய்தால் application fail ஆகலாம்.

## Index add செய்வதற்கு முன் execution plan படிங்க

```sql
EXPLAIN (ANALYZE, BUFFERS)
SELECT product_id, SUM(amount)
FROM orders
WHERE status = 'PAID'
  AND ordered_at >= DATE '2026-06-01'
GROUP BY product_id;
```

Execution plan database உண்மையில் எவ்வளவு work செய்தது என்பதை காட்டும். Index selective reads-ஐ faster ஆக்கலாம்; ஆனால் storage மற்றும் write cost add பண்ணும். எல்லா columns-க்கும் index உருவாக்காமல் measured access pattern அடிப்படையில் design பண்ணுங்க.

```sql
CREATE INDEX idx_orders_paid_date_course
ON orders (ordered_at, product_id)
WHERE status = 'PAID';
```

## Parameterised query மூலம் values-ஐ protect பண்ணுங்க

Unsafe:

```python
sql = "SELECT * FROM customers WHERE email = '" + email + "'"
```

Safe approach-ல் value SQL code-லிருந்து separate-ஆக இருக்கும்:

```python
statement = text("SELECT customer_id FROM customers WHERE email = :email")
connection.execute(statement, {"email": email})
```

Prepared statement மற்றும் parameter binding use செய்தால் database code மற்றும் data-வை distinguish பண்ண முடியும். Table name போன்ற dynamic identifiers-க்கு strict allow-list தேவை; ordinary value மாதிரி parameterise பண்ண முடியாது.

## Transaction complete change-ஐ protect பண்ணும்

Payment record மற்றும் order confirmation இரண்டும் commit ஆக வேண்டும் அல்லது இரண்டும் rollback ஆக வேண்டும். Transaction-ஐ focused-ஆ வைத்திருங்க, failures-ஐ explicit-ஆ handle பண்ணுங்க, database locks open-ஆ இருக்கும்போது slow LLM network call பண்ணாதீங்க.

## AI-generated query-க்கு production controls

| Control | ஏன் தேவை? |
|---|---|
| Read-only role | Mutation prevent பண்ண |
| Table/column allow-list | Data exposure limit பண்ண |
| Query timeout | Resource use bound பண்ண |
| Mandatory limit | Returned rows control பண்ண |
| Audit event | யார் என்ன query கேட்டார் என்று preserve பண்ண |
| Redaction | Logs மற்றும் model context-ல் sensitive values protect பண்ண |

## Beginners செய்யும் common mistakes

<Mistakes>

- Execution plan மற்றும் workload check பண்ணாமல் index add பண்ணுவது.
- User அல்லது model text-ஐ concatenate செய்து SQL build பண்ணுவது.
- Reporting service-க்கு write permission கொடுப்பது.

</Mistakes>
