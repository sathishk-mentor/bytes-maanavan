## “Best customers” என்பது இன்னும் SQL-ready question இல்லை

**Best** என்றால் revenue-ஆ, margin-ஆ, order count-ஆ? இந்த ambiguity-ஐ resolve செய்யாமல் SQL generate செய்தால் syntax சரியாக இருந்தாலும் wrong business question-க்கு answer வரலாம்.

## Safe workflow-ல் பல gates இருக்க வேண்டும்

1. Question மற்றும் authorised user context-ஐ புரிந்துகொள்ளுங்கள்.
2. Ambiguous metric மற்றும் time range-ஐ clarify செய்யுங்கள்.
3. Approved schema, business definitions மட்டும் retrieve செய்யுங்கள்.
4. Bounded query generate செய்யுங்கள்.
5. Statement, tables, columns, operations validate செய்யுங்கள்.
6. Read-only role, timeout, cost, row limits-உடன் execute செய்யுங்கள்.
7. Result மற்றும் query context-ஐ explain செய்யுங்கள்.
8. Request, decision, SQL, execution metadata-ஐ audit log-ல் பதிவு செய்யுங்கள்.

Agent இந்த gates-ஐ order-ஆக pass செய்ய வேண்டும்: generate செய்வதற்கு முன்பு clarify, execute செய்வதற்கு முன்பு validate, permission boundary வந்தால் stop.

## தெளிவான question-க்கு governed query

```sql
SELECT c.customer_id, c.name,
       SUM(o.total_amount) AS paid_revenue
FROM analytics.customers AS c
JOIN analytics.orders AS o
  ON o.customer_id = c.customer_id
WHERE o.status = 'PAID'
  AND o.ordered_at >= DATE '2026-09-01'
  AND o.ordered_at < DATE '2026-10-01'
GROUP BY c.customer_id, c.name
ORDER BY paid_revenue DESC, c.customer_id
LIMIT 5;
```

இந்த request metric, status, time range, result size அனைத்தையும் define செய்கிறது. ஒரு SQL view useful building block; ஆனால் அது மட்டும் complete semantic governance system அல்ல.

## Prompt அல்ல, permissions தான் boundary enforce செய்யும்

```sql
CREATE ROLE reporting_agent NOLOGIN;
GRANT USAGE ON SCHEMA analytics TO reporting_agent;
GRANT SELECT ON ALL TABLES IN SCHEMA analytics TO reporting_agent;
```

“DELETE செய்யாதே” என்று prompt-ல் எழுதுவது access control அல்ல. Database role-க்கு DELETE privilege இல்லாமல் வைத்தால் generation தவறினாலும் action block ஆகும்.

## Execute செய்வதற்கு முன்பு validate செய்யுங்கள்

- Approved statements, schemas, tables, columns மட்டும் allow செய்யுங்கள்.
- Multiple statements மற்றும் evasion patterns-ஐ reject செய்யுங்கள்.
- Statement timeout, maximum rows, resource limits பயன்படுத்துங்கள்.
- Costly query-க்கு `EXPLAIN` அல்லது dry run consider செய்யுங்கள்.
- Sensitive values-ஐ redact செய்து audit trail வைத்திருங்கள்.

## பொதுவான mistakes

<Mistakes>

- Valid syntax என்றால் correct answer என்று நினைப்பது.
- எல்லா production tables-க்கும் direct access கொடுப்பது.
- Database permission-க்கு பதிலாக model prompt-ஐ நம்புவது.
- Vague metric அல்லது date-ஐ clarify செய்யாமல் execute செய்வது.
- Definition மற்றும் freshness இல்லாமல் ஒரு number மட்டும் return செய்வது.

</Mistakes>

## Interview-ல் எப்படி explain செய்வது?

<ThemeCard title="Prompt-only SQL safety ஏன் போதாது?" badge="CLEAR ANSWER">

## Beginner FAQ

**ஒவ்வொரு query-க்கும் approval வேண்டுமா?** Strict controls உள்ள low-risk read-only query automatic-ஆ run ஆகலாம். Sensitive, costly அல்லது consequential request review கேட்க வேண்டும்.
